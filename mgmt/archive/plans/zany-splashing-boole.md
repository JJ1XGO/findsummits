# FR-014 を機能分解し FR-004/FR-007/FR-022 に責務を吸収

## Context

直前のコミット（`fec2fb4`）で SRS フェーズ2 を 2-1/2-2 に分割し、FR-022「コル充足判定」を新設した。しかし FR-014「独立峰のコル探索」が依然として「対象ピーク座標 → メッシュコード変換 / N² パターン探索 / 早期終了 / 広域 CSV 出力」といったオーケストレーションをまとめて抱えており、独自の計算ロジックを持たない「中身のない FR」になっている。

ユーザー方針:
- **FR-014 を独立プログラムとして実装するつもりはない**。基本は FR-004/FR-002/FR-003/FR-015/FR-005/FR-006/FR-007 を再利用する
- FR-014 の責務を既存 FR に分解し、足りない記述を各 FR に書き足す
- **FR-022 がコル未確定ピークを抽出して座標リストと N を FR-004 に渡す**。FR-004 以降は 3×3 と同じパイプラインで処理する
- N² パターン探索は廃止し、**FR-004 が N≥4 時に内部で 4 コーナー（NW/NE/SW/SE）パターンを生成・処理**する
- FR-014 自体は **見出しだけ残し『広域解析は FR-004 (N≥4 モード) と FR-022 で実現する』としてスタブ化**する（フェーズ2-2 が広域解析であることと実現方法の概要は残したい）

目標: 「FR-014 = 独自ロジックなしのオーケストレーション」だった状態を解消し、機能 FR の粒度を揃える。

## 設計判断（決定済み）

| 項目 | 内容 |
|---|---|
| N×N パターン配置 | 4 コーナー（NW/NE/SW/SE）の 4 パターンのみ。N² パターン探索は廃止 |
| 4 コーナー生成の所在 | **FR-004 内部**（N≥4 モード時）。FR-022 はピーク座標リスト + N を渡すだけ |
| N エスカレーション | FR-022 が管理（4→5→6）。1 つの N について FR-004 を1回呼ぶ |
| 対象ピーク → メッシュコード変換 | FR-004 内部（N≥4 モード時） |
| 早期終了（key_col_resolved=true） | FR-004 内部（4 パターンの早期終了）+ FR-022（N エスカレーションの早期終了） |
| 対象ピーク行のみ出力 | FR-007 に明記（広域モード時のフィルタ動作） |
| 広域 per-mesh CSV 命名規則 | FR-007 に明記（通常と区別できる命名・詳細は HLD） |
| FR-014 の扱い | **スタブ化**（見出し + 1〜2 段落の概要のみ残す。本体は「FR-004 (N≥4 モード) と FR-022 を参照」へ） |
| フェーズ2-2 の扱い | 見出しと導入文は残す（広域解析の概念とどう実現するかを示す） |

### 4 コーナー方式の根拠

「コル探索の最大距離」の比較:
- 中央配置 N×N: 半径 (N-1)/2 メッシュ（全方位均等だが距離が短い）
- **コーナー配置 N×N: 対角まで (N-1)√2 ≒ 1.4(N-1) メッシュ**（1方向だが遠い）
- N² パターン探索: 全方位 + 遠距離だが N² 回試行（過剰）

4 コーナー（NW/NE/SW/SE）試行: 全方位カバー + 遠距離（√2(N-1)）を両立し、N² → 4 に大幅圧縮。

## 変更内容

### A. FR-004「メッシュ結合解析」の N≥4 モード明示化

現状の FR-004 は N≥4 時の挙動が「ズームレベル14 + 2×2 max pooling」のみ書かれている。以下を追記:

**入力テーブルに追加**:

| データ名 | 必須/任意 | デフォルト（任意時） | 備考 |
|---|---|---|---|
| 対象ピーク座標リスト | 任意 | —（N=3 時は不要） | N≥4 モード時に必須。FR-022 が抽出した `key_col_resolved=false` ピーク群（緯度経度） |

**処理に追記**（既存「使用タイルズームレベル」段落の後あたり）:

- **N≥4 モード（フェーズ2-2）の解析範囲決定**:
  - 各対象ピーク座標について、ピーク所属メッシュを緯度経度から算出する（[メッシュコード ↔ 緯度経度変換](00_GLOSSARY.md#mesh-to-latlon)）
  - 対象メッシュを N×N の **4 つのコーナー位置**（NW=(1,1) / NE=(1,N) / SW=(N,1) / SE=(N,N)）に置いた 4 通りの N×N メッシュコードリストを生成する
  - 各パターンについて per-mesh パイプライン（[FR-005](#fr-005-ピーク候補検出)→[FR-006](#fr-006-コル検出プロミネンス計算)→[FR-007](#fr-007-プロミネンスフィルタper-mesh-csv-出力)）を実行する
  - 対象ピークについて `key_col_resolved=true` を得たパターンが見つかった時点で早期終了（残りのコーナーパターンはスキップ）
  - 存在しないメッシュ（海域・国外等）を含むパターンはスキップする
  - FR-016 のポリゴン生成は呼び出さない（コル特定のみが目的）

**入力テーブルの解析範囲サイズ N の備考も更新**: 「フェーズ2-2 から呼び出された場合は N=4〜6 が渡される」を維持

### B. FR-007「プロミネンスフィルタ・per-mesh CSV 出力」に広域モード仕様追記

現状 FR-007 は通常モードのファイル仕様（`<meshcode>.csv`）のみ書かれている。追記:

- **広域モード（N≥4）の出力動作**:
  - **対象ピーク絞り込み**: 解析範囲内で検出されたピークのうち、FR-004 から渡された対象ピーク座標リストに含まれるピーク行のみを出力する（他のピークは出力しない。merged 統合時のノイズ防止）
  - **ファイル命名**: 通常 per-mesh と区別できるファイル名で出力する（具体的な命名規則は HLD 参照）

### C. FR-022「コル充足判定」の処理記述更新

現状 FR-022 は「FR-014 を呼ぶ」ことしか書かれていない。FR-014 が廃止に近い状態になるため、FR-022 の処理を以下に書き換える:

- **未充足ループ（N=4→5→6 のエスカレーション）**:
  1. 抽出した未確定ピーク座標リストと現在の N を **[FR-004](#fr-004-メッシュ結合解析)（N≥4 モード）** に渡して呼び出す
  2. FR-004 が広域 per-mesh CSV を出力したら、[FR-008](#fr-008-per-mesh-csv-統合) を再実行して `merged_peak.csv` を再生成する
  3. 更新後の `merged_peak.csv` を再判定する
  4. まだ未確定が残れば N を +1 して 1 を繰り返す（N の上限は 6）

`[FR-014]` への参照を全て `[FR-004]（N≥4 モード）` に置換。

### D. FR-014「独立峰のコル探索」のスタブ化

現状の本体（L546-L582 周辺）を以下にスリム化する:

```markdown
#### FR-014: 独立峰のコル探索

- **対応 UR**: [UR-007](01_URD.md#ur-007)
- **概要**: コル未確定ピーク（独立峰）について、N×N + L14 max pooling の広域モードでコル探索を行う。本機能は独立した実装を持たず、**[FR-004](#fr-004-メッシュ結合解析) の N≥4 モード** と **[FR-022](#fr-022-コル充足判定)** の連携で実現する。

**実現方式**:

- [FR-022](#fr-022-コル充足判定) がコル未確定ピークを抽出し、ピーク座標リストと N（4→5→6 のエスカレーション）を [FR-004](#fr-004-メッシュ結合解析) に渡す
- [FR-004](#fr-004-メッシュ結合解析) が N≥4 モードで、各対象ピークについて N×N の **4 コーナー配置パターン**（NW/NE/SW/SE）を内部で生成・解析し、`key_col_resolved=true` を得たパターンで早期終了する
- 後段の [FR-005](#fr-005-ピーク候補検出)/[FR-006](#fr-006-コル検出プロミネンス計算)/[FR-007](#fr-007-プロミネンスフィルタper-mesh-csv-出力) は 3×3 モードと同じパイプラインで処理する（広域モードでは [FR-016](#fr-016-ピーク域ポリゴン生成) は呼び出さない）

詳細・設計判断は [ADR-SRS-004](decisions/ADR-SRS-004-level14-max-pooling-isolated-peaks.md) を参照。
```

これにより:
- FR 番号 014 は維持（欠番回避）
