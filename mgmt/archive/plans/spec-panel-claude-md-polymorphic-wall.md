# 計画: プロジェクト CLAUDE.md「プロジェクト概要」を簡潔化

## Context（なぜ）

プロジェクト CLAUDE.md の「プロジェクト概要」（L5-14）が冗長で、口語的な filler（「当然〜」「一応データとしては〜」「〜な形のO/Pにする必要がある」）と長い run-on の箇条書きを含む。内容は URD（`docs/10_URD.md`）とほぼ完全に重複している:

- O/P 3点 → UR-004 / UR-005 / UR-006
- 変更・削除の識別 → UR-003
- DEM フォールバック順 → URD §5「DEM5a / DEM5b / DEM5c / DEM10b の優先順」

spec-first 原則では CLAUDE.md は要件を再掲せず URD を正として指すべき。ゴール: 概要を「何を作るツールか」が一目で分かる要点＋URD 参照に圧縮する。DEM フォールバックの精密規則は coding 時に有用なため1行残す。

## 設計判断（ユーザー確認済み）

圧縮度 = **要点＋3点箇条書き + URD 参照**（DEM フォールバック行は残す）。

## 対象ファイルと変更内容

`/workspace/CLAUDE.md` の L5-14「## プロジェクト概要」セクションを以下へ置換する（lint クリーンな markdown 形式）:

```markdown
## プロジェクト概要

国土地理院の標高タイル（DEM5/DEM10b）を解析し、SOTA 日本支部のサミットリスト更新申請に必要な成果物を生成する支援ツール。

主な成果物は3点:

- **申請書 XLSX**（最重要）: SOTA 日本支部指定フォーマット（追加/変更/削除）
- **エビデンス CSV**: サミット／Keyコルの座標・標高・プロミネンス
- **目視確認用 GeoJSON / HTML ビューア**: 地理院地図上での検証用

現行リストとの差分（新規・変更・削除）も識別する。要件の正は [`docs/10_URD.md`](docs/10_URD.md)。

標高値は dem5a → dem5b → dem5c → dem10b の順でフォールバックする（各座標で「タイルなし」または「無効値」なら次のソースへ）。
```

他セクションは変更しない。

## モデル運用

単一セクションの置換のみ。**Sonnet 推奨**。
