# FR-008 レビュー反映 計画

## Context

SRS の FR-008（per-mesh CSV 統合）レビューで 6 件の指摘を洗い出し、すべて決着した。
中心は「入力としての per-mesh CSV / 1次メッシュコードリストの意味が曖昧」という問題で、
討議の結果 **入力を 2 リストに分離する TOBE 設計**に決定した。本計画はその決定を
SRS・データ辞書・ADR・トラッカーへ整合反映する。コードは仕様確定後に別途追従する
（仕様優先原則）。

## 決定事項（確定済み）

1. **(2)+(3) 入力 2 リスト分離 — 設計判断（ADR 化）**
   - `対象1次メッシュコードリスト`（ユーザー入力・任意・デフォルト=日本全土）＝ **入力フィルタ**。
     - 指定時: 指定 meshcode の**通常 per-mesh CSV のみ**統合。**広域 per-mesh は対象外**。
     - 未指定（=全土）時: ディレクトリ内の**通常+広域すべて**統合（フルパイプライン）。
   - `日本全土1次メッシュコードリスト`（内部データ・必須・**新規追加の入力**）＝ **expected_count 算出基準**。
   - `expected_count` は**常に全土基準**で 3×3 隣接カウント（通常モード行のみ／広域行は空欄）。
     → 範囲端ピークは `analysis_count < expected_count` で正しく `unstable` 判定。
     → 「リスト省略時 expected_count 空欄」問題は消滅（(3) 解決）。
   - FR-022 エスカレーションループ内部の FR-008 再実行は `対象リスト` を渡さず全土デフォルトで動作。
2. **(6) 代表採用ロジックの完全定義**
   1. `key_col_resolved=true` を false より優先
   2. true 同士は `col_elev` 降順（最高＝保守的）
   3. 同値時タイブレーク: **通常(L15)優先 → analysis_id 昇順**（NFR-003 決定論担保）
   4. 全件 false の場合は `key_col_resolved=false` 維持 → FR-022 がエスカレーション対象に拾う
3. **(1)(4)(5) 文言整理**（仕様判断なし）
   - (1) per-mesh CSV 入力欄に所在・読み込み範囲を明記
   - (4) 概要 `≥150m` → 「プロミネンス最終フィルタ閾値以上（デフォルト150m）」
   - (5) `merged_peak.csv` の保存先パスを出力表・データ辞書に明記
4. **テスト性**: FR-008 仕様変更を要する阻害要因なし（fixture 駆動コンポーネントテスト + 小ブロック実解析 IT の 2 段構成で対応可能）と確認。記録は不要。
