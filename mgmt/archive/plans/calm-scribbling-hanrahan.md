# SRS 機能要件（FR）体裁統一

## Context

SRS（`docs/02_SRS.md`）の 4 章「機能要件」セクションは、FR ごとに小見出しラベル・入出力テーブルのカラム構成がばらついており、読み手が同じ情報を同じ位置で探せない。直前のセッションで「外部I/F・ユーザ入力・内部データ」の三分類規約（ADR-SRS-016）を策定したが、機能要件側にはまだ反映されていない。

本作業の目的:

1. FR ごとに散在する `**処理**:` / `**詳細**:` ラベルを統一する
2. 各 FR の入出力テーブルに「種別」列（外部I/F / ユーザ入力 / 内部データ）を追加し、ADR-SRS-016 の三分類を機能要件レベルで可視化する
3. 入出力テーブルのカラム構成（特に備考列の有無）を全 FR で統一する

これにより、機能要件と外部I/F・ユーザ入力・内部データ仕様（6章・7章）の対応関係が一目で追えるようになる。

## 統一方針

### A. 説明ラベルの統一

- `**処理**:`（5 FR で使用）と `**詳細**:`（16 FR で使用）を **`**説明**:`** に統一する
- 配置順は現状維持（概要 → 入力 → 出力 → 説明 → 異常系）

### B. 入力テーブルの統一フォーマット

```
| データ名 | 種別 | 必須/任意 | デフォルト（任意時） | 備考 |
```

- 種別の値: `外部I/F` / `ユーザ入力` / `内部データ` / 空欄（判定不能時）
- 既存の備考列がない FR は備考列を追加し、内容なしの場合は `—` で埋める

### C. 出力テーブルの統一フォーマット

```
| データ名 | 種別 | 形式 | 備考 |
```

- 種別の値: `外部I/F` / `内部データ` / 空欄（判定不能時）
- 既存の備考列がない FR は備考列を追加し、内容なしの場合は `—` で埋める

### D. 適用対象外

- **FR-014**（独立峰のコル探索）: 独自構造（`**実現方式**:` `**入出力・トリガー条件**:`）を現状維持。本作業の対象外
- **FR-013 内のフィーチャプロパティ表**（Point/Polygon/LineString 群）: 既に独自フォーマットで安定しているため変更しない
- **FR-011・FR-012 内のカラム説明表**: 出力テーブルとは別の独立した表のため変更しない

## 作業手順

1. FR-001 から SRS 記載順（4.1 → 4.6）に従って 1 FR ずつ修正
2. 各 FR で:
   - 入力テーブルに「種別」列を追加、備考列がなければ追加
   - 出力テーブルに「種別」列を追加、備考列がなければ追加
   - `**処理**:` または `**詳細**:` を `**説明**:` に置換
3. 全 FR 修正後、`grep` で `**処理**:` `**詳細**:` の残存が無いことを確認
4. テーブルのカラム数が入力 5 列・出力 4 列で揃っていることを `awk` で検証

## 検証

```bash
# 残存ラベルが無いことを確認
grep -n "^\*\*処理\*\*:\|^\*\*詳細\*\*:" /workspace/docs/02_SRS.md
# → 出力なし（FR-014 を除き）

# 入力テーブルが 5 列・出力テーブルが 4 列で統一されていることを確認
awk '/^#### FR-/{fr=$0} /^\*\*入力\*\*/{mode="in"} /^\*\*出力\*\*/{mode="out"} mode!="" && /^\| データ名/{print fr, mode, NF-1, "cols"}' /workspace/docs/02_SRS.md
# → FR-014 を除く全 FR で入力 5 / 出力 4

# 種別列の値が想定値のみであることを確認
grep -n "^| " /workspace/docs/02_SRS.md | grep -v "データ名\|---" | awk -F'|' '{print $3}' | sort -u
# → 外部I/F / ユーザ入力 / 内部データ / 空欄 のみ
```
