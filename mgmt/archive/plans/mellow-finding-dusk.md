# SRS 改訂: 北方領土除外をタイル取得段階に前倒し / 4.1・4.2 入れ替え

## Context

先日の FR-001 / FR-017 SRS レビューを踏まえた追加改訂。

現行 SRS では北方領土除外は「FR-001 で全タイル取得 → FR-017 で除外リスト生成 → FR-004 がタイル読み込み時に NODATA マスク」というデータフロー。

ユーザー提案によりこれを「FR-017 で除外リスト生成 → FR-001 が読んで取得対象から除外」に前倒しすることで:

- 北方領土タイルの通信・容量・時間が削減される
- FR-004（C エンジン）から「除外リスト読み込み + NODATA マスク」処理が消え、C エンジンは「ローカルキャッシュにあるタイルが全て解析対象」という素直な構造になる
- 北方領土除外という業務ルールが SRS 上の入口（タイル取得段階）で完結する

合わせて 4.1 / 4.2 のセクション番号も入れ替え、依存順（前処理 → 取得）と章立てを一致させる。

## スコープ

本タスクは **SRS 改訂のみ**。コード追従は別 ISSUE（ISSUE-056・ISSUE-079）で対応する。

### 1. SRS 章構造の入れ替え（4.1 / 4.2）

|---|---|
| 4.1 タイル取得コンポーネント（FR-001） | 4.1 行政区域前処理コンポーネント（FR-017） |
| 4.2 行政区域前処理コンポーネント（FR-017） | 4.2 タイル取得コンポーネント（FR-001） |

- 目次（L26 / L28）の順序も入れ替え
- アンカーリンク `#41-...` / `#42-...` の参照は他文書になし。SRS 内 2 箇所のみ

### 2. 3.2 主要コンポーネント構成（L148-L159）

- 「行政区域前処理コンポーネント」行を「タイル取得コンポーネント」行より上に移動
- 行政区域前処理の主要出力を実態に合わせ更新:
  - 現行: 「軽量化された境界 GeoJSON」
  - 改訂後: 「N03 前処理済み地域 GeoJSON / 市区町村 GeoJSON / 北方領土除外タイルリスト」
- タイル取得の主要入力に「北方領土除外タイルリスト」を追加

### 3. 3.3.1 機能要件のフェーズ配置マトリクス（L163-L188）

- 表内行順序を入れ替え: 「行政区域前処理 / FR-017」を「タイル取得 / FR-001」より上に
- フェーズ配置のマーカーを「○」→「✅」に全置換（視認性改善・FR 全行が対象）
- フェーズ配置自体（どの FR がどの Phase に該当するか）は変更なし

### 4. 3.3.2 処理フロー俯瞰図（L190-L229）

フェーズ1 部分を次のように書き換える:

```
【フェーズ1: 前処理・タイル取得】
行政区域前処理コンポーネント           N03 行政区域前処理（初回のみ）
       ├─ N03 前処理済み地域 GeoJSON     ← 統合・突合コンポーネントが参照
       ├─ N03 前処理済み市区町村 GeoJSON ← 統合・突合コンポーネントが参照
       └─ 北方領土除外タイルリスト       ↓
タイル取得コンポーネント              タイル事前取得（北方領土除外タイルリストでスキップ）
       ↓ ユーザーが解析コマンドを実行
```

### 5. FR-001（標高タイル事前取得）改訂

**入力テーブル**:

| データ名 | 種別 | 必須/任意 | デフォルト（任意時） |
|---|---|---|---|
| 1次メッシュコードリスト | ユーザー入力 | **任意** | **日本全土１次メッシュコードリスト** |
| 日本全土１次メッシュコードリスト | 内部データ | 必須 | — |
| **北方領土除外タイルリスト** | **内部データ** | **必須** | **—** |
| 地理院標高タイル | 外部I/F | 必須 | — |

**説明欄に追記**:
- 「取得対象タイル範囲から、北方領土除外タイルリストに含まれるタイル（ズームレベル 15 の x/y 整数ペア）を除外する。除外タイル分は HTTP リクエストを発行しない」
- 「北方領土除外タイルリスト未存在時はエラー終了する（必須のため）」

### 6. FR-017（N03 行政区域前処理）改訂

- 概要 3 つ目の bullet（L279）: 「タイル読み込み段階（FR-004）で除外したい」→「タイル取得段階（FR-001）で除外したい」
- フォールバック節（L316）: 「北方領土除外タイルリストが未生成の場合: FR-004 は北方領土タイルの NODATA 化をスキップする」を削除（FR-001 が必須前提なので、未生成時はそもそも FR-001 が走らない）

### 7. FR-004（メッシュ結合解析）改訂

- 「北方領土タイル除外」段落（L375）を削除
- FR-004 は「ローカルキャッシュにあるタイルを読み込む」という単純な構造に戻る

### 8. データ辞書（7.2 / 7.2.1）

- 7.2 内部データ一覧（L1419）: 「北方領土除外タイルリスト」の利用者を「FR-004」→「FR-001」に変更
- 7.2.1 北方領土除外タイルリスト詳細（L1450-L1457）: 用途欄を「タイル読み込み時に参照し全ピクセルを NODATA」→「タイル取得時に参照し該当タイルを取得対象から除外」に変更

### 9. その他の文中参照

- L1492 / L1508 など本文中の「除外方法は FR-004・FR-017 で規定」を「除外方法は FR-001・FR-017 で規定」に修正

### 10. ADR-SRS-018 新規作成

判断要素（タイル取得段階で除外する方式選択）を ADR として記録。

- ファイル名: `docs/decisions/ADR-SRS-018-northern-territories-skip-at-tile-fetch.md`
- 状態: 採用・未実装
- 内容:
  - Context: 元の方式（FR-004 でマスク）と新方式（FR-001 でスキップ）の選択肢
  - Decision: タイル取得段階で除外
  - Alternatives: (a) FR-004 でマスク（現行案）、(b) FR-001 で取得スキップ（採用案）の比較
  - Consequences: C エンジン責務縮小・通信量削減・FR-017 が FR-001 の必須前提化
