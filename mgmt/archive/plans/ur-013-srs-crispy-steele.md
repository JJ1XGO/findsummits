# UR-013 の SRS 反映（第1段：観測可能性 NFR 化）

## Context

UR-013（中間成果物の生成タイミングでの可視化＝観測可能性。ADR-URD-016 で新設）が
URD に追加されたが、SRS 側に受け皿が無く、UR-013 → SRS のトレースが切れている。
この欠落が原因で FR-018 のループ内再入設計が過去に何度も揺れた。

UR-013 は性質の異なる2つの要求を含む:
1. **観測可能性**: 中間成果物（per-mesh / 統合 GeoJSON）を生成タイミングで地図に出して妥当性確認できる（横断的品質特性）
2. **ピーク↔コル対応の可視化**: コル位置を地図で確認できる（現行 GeoJSON はコル座標を持たない＝ISSUE-106）

本計画は**第1段（①観測可能性の受け皿確立）のみ**を対象とする。
②ピーク↔コル対応の表示方式は ISSUE-106 として別セッションで実データ確認しながら詰める（スコープ外）。

①の出力実体は既に存在する: FR-016 が per-mesh `activation.geojson` を、FR-018 が統合版
`merged_activation.geojson` を物理ファイルとして残す仕様があり、手動ドラッグ＆ドロップで
地図に乗せられる。足りないのは「根拠となる NFR とトレース」だけ。

## 反映方針

### 1. NFR-009「観測可能性（中間成果物の可視化）」を新設
`docs/20_SRS.md` の「5. 非機能要件」末尾（NFR-008 の後）に追加。既存 NFR と同じ
「**対応 UR**」明記形式に揃える。文面ドラフト:

```
### NFR-009: 観測可能性（中間成果物の可視化）

- **対応 UR**: UR-013
- 解析パイプラインが各段階で生成する中間成果物（per-mesh アクティベーションゾーン
  GeoJSON（FR-016）・統合済みピーク域 GeoJSON `merged_activation.geojson`（FR-018））を、
  生成されたタイミングで物理ファイルとして出力し、地理院地図等の地図ソフトに読み込んで
  （手動ドラッグ＆ドロップ可）位置・形状の妥当性を目視確認できること
- 中間 GeoJSON は申請エビデンス（UR-006）ではなく、開発・テスト・運用時の妥当性検証を
  目的とする。デバッグ・差分検査のため物理出力を残す（FR-018 の merged_activation.geojson は
  世代ごとに上書き再生成）
- **保証範囲外**: ピーク・コルの「対応関係」の精密な可視化は本 NFR の対象外とし、別途 SRS
  設計で扱う（現行 GeoJSON はコル座標を持たない＝ADR-SRS-022 の join 方式。ISSUE-106 参照）
```
（リンクは SRS 既存記法の Markdown アンカーに合わせる）

### 2. 既存 FR への相互リンク（最小限）
- FR-018 の「目的」記述（待ち時間中に各世代を地理院地図で確認）に NFR-009 への参照を1つ追加。
- FR-016 は本文に「対応 UR」欄が無いため追記不要。トレースは NFR-009 側で閉じる。
- 大きな本文変更はしない（①の機能実体は既存仕様で充足済みのため）。

### 3. 目次更新
`docs/20_SRS.md` 冒頭の目次の NFR セクションに NFR-009 を追記。

### 4. ADR-SRS-025 を作成
`docs/decisions/ADR-SRS-025-observability-nfr-and-peak-col-scope-split.md`
- **Context**: UR-013/ADR-URD-016 を SRS にどう落とすか
- **Decision**: (a) 観測可能性を NFR-009 で受ける（FR ではなく品質特性として）、
  (b) ①の出力実体は既存 FR-016/FR-018 がカバー済みとして新規 FR を起こさない、
  (c) ②ピーク↔コル対応の表示方式は ISSUE-106 としてスコープ分離する
- **Alternatives**: FR で受ける案 / ISSUE-106 を同時解決する案 / 専用の中間可視化 FR を新設する案
- **Consequences**: FR-018 ループ内再入の根拠が SRS 内で閉じる。②は別途必要。
