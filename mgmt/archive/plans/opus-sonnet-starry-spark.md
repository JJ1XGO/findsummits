# 計画=Opus／実装=Sonnet 運用の強化（計画駆動方式）

## Context

「計画は Opus、実装は Sonnet」という運用が最近薄れている。原因は、モデル使い分けの拠り所が
**その場限りの口頭推奨**（CLAUDE.md 原則#4 の「ExitPlanMode 承認直後に Sonnet を促す」）であり、
セッションをまたぐと揮発して引き継がれない点にある。

ユーザーは今後、**計画を作って承認するセッション（Opus）と、計画に従って実行するセッション（Sonnet）を
分ける運用**に移行したい。この分離運用では「承認時の口頭推奨」は実装セッションに届かない。

対応方針: **モデル選択を永続データである計画ファイル（タスク毎）に書き込み、実装セッションは
計画を正としてモデルを確認・切替して進める。** モデル切替はユーザーが `/model` で実行する。
既存の実装編集ゲート（PreToolUse hook）は最後の安全網として残しつつ綻びを補修する。

役割分担（三層）:

1. **計画 = 全タスクのモデルの正**（永続・セッション非依存）
2. **行動ルール（CLAUDE.md）= 計画のモデルを読み、現セッションと違えばユーザーに切替を促す**
3. **実装編集ゲート = 実装ファイル（コード+HTML）を Opus で編集したら止める最後の砦**

## 決定事項（ユーザー合意済み）

- 計画にモデルを書く粒度は **A案: タスク毎に明記・既定 Sonnet**。難所（複雑アルゴリズム・難解な
  デバッグ・仕様解釈が揺れる等）のみ Opus を理由付きで指定。
- モデル切替（`/model`）は**ユーザーが実行**する（Claude は促すだけ）。
- ゲート対象に `.html`（地理院地図ビューア＝実装成果物）を追加。`docs/` 配下の `.md` は対象にしない
  （仕様執筆＝設計＝Opus が正のため、巻き込むと誤検知になる）。`.geojson` は生成物のため対象外のまま。

## 変更内容

### 1. 計画テンプレート規約（タスク毎モデル列）

- `mgmt/plan.md` のタスク一覧に **「モデル」列／注記**を設け、各タスクに `Sonnet`（既定）または
  `Opus`（理由付き）を明記する。
- 規約は **プロジェクト `CLAUDE.md` の「計画ファイル・handover の扱い」セクション**に1項追記:
  「計画の各タスクに実行モデルを明記する（既定 Sonnet、Opus は理由併記）。実装セッションはこの指定を
  正とする」。

### 2. グローバル CLAUDE.md 原則#4 改訂

ファイル: `/home/node/.claude/CLAUDE.md`（原則「### 4. モデルを使い分ける」）

- **計画作成時**: 計画の全タスクに実行モデルを埋める（既定 Sonnet、Opus は理由付き）を必須化する一文を追加。
- **実装セッション（分離運用）**: 「タスク着手時に計画のモデル指定を読み、現在のセッションモデルと
  異なれば、編集を始める前にユーザーへ `/model` 切替を促してから進む（切替はユーザーが実行）」を追加。
- 既存の単一セッション向け記述（ExitPlanMode 承認直後に推奨を伝える）は維持しつつ、
  「推奨は計画ファイルに書き残す」と接続させる。

### 3. 実装編集ゲート補修

ファイル: `/workspace/.claude/settings.local.json`（PreToolUse hook、matcher `Write|Edit`）

- ファイル判定の `case "$f" in *.c|*.h|*.py)` を **`*.c|*.h|*.py|*.html)`** に拡張。
- メッセージ内の **「CLAUDE.md 原則#5」を「原則#4」に修正**（現行の番号ズレ）。
- メッセージに「**新規の実装セッションが Opus のままの可能性**があります。計画のモデル指定を確認し、
  Sonnet 指定なら `/model` 切替をユーザーに促してください」という分離運用向けの一文を追加。
- `permissionDecision` は `ask` のまま（Opus 継続が正当な場面があるためブロックしない）。

### 不採用（今回の方針で代替済み）

- ExitPlanMode 承認時リマインド hook → 分離運用では実装セッションに届かず、発火可否も未確認。
  計画ファイルへのモデル記載（永続）で代替。
- SessionStart フェーズ検出リマインド → SessionStart 時点ではモデルを確実に判定できず、フェーズ推測も
  曖昧。計画＝フェーズ指標とすることで不要。

## 対象ファイル

- `/workspace/CLAUDE.md` — 計画テンプレート規約の追記
- `/workspace/.claude/settings.local.json` — ゲートの `.html` 追加・#5→#4・文言追加

## 検証

1. **settings.local.json**: `jq . settings.local.json` で JSON 妥当性確認。
   hook の case 文を切り出し、`f=foo.html` で当該分岐に入ること・`f=docs/20_SRS.md` で
   `exit 0`（対象外）になることをシェルで dry-run 確認。
2. **グローバル CLAUDE.md**: 編集すると PostToolUse hook が claude-md-panel レビューを促す想定。
   `venv/bin/python3 -m pymarkdown -c /workspace/.pymarkdown scan` で警告ゼロ確認。
3. **プロジェクト CLAUDE.md**: `make lint`（lint-md）で警告ゼロ確認。
4. **コミット**: ドキュメント更新ルールに従い、編集ターン内に Conventional Commits でコミット
   （`/workspace` 配下のみ。グローバル CLAUDE.md は git 管理外）。push は別途指示まで不要。

## 補足

- 本タスクの実装は `.md`/`.json` 編集が中心で機械的。複雑な設計判断は伴わないため **Sonnet 推奨**。
