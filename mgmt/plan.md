# SRS フェーズ2 を 2-1/2-2 に分割し、コル充足判定 FR を新設

## Context

現状の SRS（`docs/02_SRS.md`）では:
- フェーズ2「ピーク解析（per-mesh）」が 3×3 解析（通常モード）と広域 N×N 解析（独立峰再解析）の双方をカバーする曖昧な括りになっている
- 広域 N×N 解析は実体としては **FR-014 がフェーズ3 に同居** していて、データフロー上「ピーク解析」と「ピーク統合」の境界がにじんでいる
- FR-014 が **N=4→5→6 のエスカレーションと FR-008 の再呼び出しを内部に隠蔽**しており、SRS 上はループ構造が見えない
- フェーズ4 への移行条件（全ピーク `key_col_resolved=true`）が暗黙で、FR-009 が前提を検査して異常終了する形になっている

目標: フェーズ境界を「per-mesh 解析」「広域メッシュ解析」「全国統合」の役割で明示分離し、フェーズ4 への移行を担う **コル充足判定 FR** を新設してループ構造を SRS 上で可視化する。

## 変更対象ファイル

- `docs/02_SRS.md`（唯一の編集対象）
- `docs/decisions/ADR-SRS-004-level14-max-pooling-isolated-peaks.md`（FR-014 の責務範囲が変わるため確認、参照表現の更新があれば修正）

## 確定事項（ユーザー合意済み）

| 項目 | 内容 |
|---|---|
| 新規 FR 名称 | **コル充足判定**（Key コルはプロジェクト内で単に「コル」と呼ぶ規約） |
| N エスカレーションの所在 | 新規 FR（コル充足判定）が N=4→5→6 のリトライカウンタを管理。FR-014 は「単一 N + 対象ピークリスト」を受ける単発機能に簡略化 |
| 新規 FR の所属フェーズ | **フェーズ3 末尾**（フェーズ4 ではない） |
| ループ構造 | フェーズ3（FR-008→FR-018→コル充足判定） → 不合格なら フェーズ2-2（FR-014）→ FR-008 再実行 → コル充足判定（N+1） |
| 最終失敗時の挙動 | N=6 まで使い切っても未解決ピークが残る場合は処理続行。FR-009 の `is_key_col_unresolved` 不備フラグで異常終了する（現行どおり） |
| FR 番号 | 新規は **FR-022** |
| ドキュメント構造 | `### フェーズ2:` を削除し `### フェーズ2-1:`・`### フェーズ2-2:` をフェーズ1/3 と同レベル（level-3）の兄弟として並べる。FR は従来どおり `####`（level-4） |

### E. FR-014 の単一N化（移動先：フェーズ2-2 配下）

**変更前（フェーズ3 内のループ責務つき）→ 変更後（単一 N 単発実行）**:

- 概要: 「`merged_peak.csv` の `key_col_resolved=false` ピークに対して、指定された **対象ピークリスト** と **N** で広域モードの per-mesh パイプライン（[FR-004] N×N + L14 max pooling）を呼び出し、広域 per-mesh CSV を生成する。コル充足判定（[FR-022]）からの単発呼び出しで動作する」
- フェーズ位置記述「フェーズ3（統合の直後…）に位置する」を削除（フェーズ2-2 に明示移動するため）
- 入力テーブルに「対象ピークリスト」「N」を追加:

  | データ名 | 必須/任意 | デフォルト（任意時） | 備考 |
  |---|---|---|---|
  | 対象ピークリスト | 必須 | — | コル充足判定（[FR-022]）が抽出した `key_col_resolved=false` ピーク群 |
  | N | 必須 | — | 4・5・6 のいずれか（コル充足判定が指定） |
  | 統合ピーク候補 work CSV（`merged_peak.csv`） | 必須 | — | 各対象ピークの所属メッシュ算出に使用 |

- 出力テーブル: 「広域 per-mesh ピーク候補 CSV」のみ残す（`merged_peak.csv` の更新は FR-008 の責務に戻すため削除）
- 詳細の **基本フロー** から内部ループ（N=4,5,6 エスカレーション・FR-008 再実行）を削除し、単発フローに書き換え:
  1. 対象ピークごとに緯度経度から所属メッシュを算出
  2. N×N メッシュコードリストを生成（対象メッシュ位置 (1,1)〜(N,N) の N² 通りを順試行）
  3. FR-004 を「処理モード = N×N + L14」で呼び出し（per-mesh パイプラインが広域モードで実行・対象ピーク行だけ出力）
  4. 各対象ピークについて全パターン探索（`key_col_resolved=true` で早期終了）
  5. 全対象ピーク分の広域 per-mesh CSV を出力して終了
- 「最終残存（N=6 でも未解消…）」「再解析トリガー」の項目はコル充足判定（FR-022）へ移管
- 「解析ウィンドウ全パターン探索」は FR-014 に残す（単一 N 内の N² パターン探索）
- ADR-SRS-004 参照は維持

### I. FR-022「コル充足判定」を新設（フェーズ3 末尾、FR-018 の次）

```markdown
#### FR-022: コル充足判定

- **対応 UR**: [UR-007](01_URD.md#ur-007)
- **概要**: `merged_peak.csv` の全ピークがコル確定（`key_col_resolved=true`）であるかを判定し、フェーズ4 への移行可否を決める。未確定ピークがある場合は N=4→5→6 のエスカレーションでフェーズ2-2（[FR-014]）を再帰的に呼び出し、`merged_peak.csv` を更新する。

**入力**:

| データ名 | 必須/任意 | デフォルト（任意時） | 備考 |
|---|---|---|---|
| 統合ピーク候補 work CSV（`merged_peak.csv`） | 必須 | — | [FR-008] 出力 |

**出力**:

| データ名 | 形式 | 備考 |
|---|---|---|
| 統合ピーク候補 work CSV（`merged_peak.csv`） | CSV | フェーズ2-2 ループ実行後の更新版（[FR-008] 再実行を経由） |
| フェーズ4 移行可否 | 判定結果（pass / 未充足のままフェーズ4 移行） | 全ピーク `key_col_resolved=true` なら pass。N=6 を使い切っても未解決が残る場合はそのままフェーズ4 へ移行（[FR-009] の `is_key_col_unresolved` 不備フラグで異常終了する） |

**処理**:

  - **判定**: `merged_peak.csv` 全行の `key_col_resolved` を検査し、未確定ピーク（`key_col_resolved=false`）を抽出する
  - **全充足**: 未確定ピークがゼロなら判定 pass。フェーズ4 へ移行する
  - **未充足ループ（N=4→5→6 のエスカレーション）**:
    1. 抽出した未確定ピーク群と現在の N をフェーズ2-2（[FR-014]）に渡して呼び出す
    2. [FR-014] が広域 per-mesh CSV を出力したら、[FR-008] を再実行して `merged_peak.csv` を再生成する（通常 per-mesh CSV と広域 per-mesh CSV を統合し、`key_col_resolved=true` のレコードがあれば代表として採用する）
    3. 更新後の `merged_peak.csv` を再判定する
    4. まだ未確定が残れば N を +1 して 1 を繰り返す（N の上限は 6）
  - **最終残存**: N=6 でも未確定ピークが残った場合、当該フラグ状態を維持したままフェーズ4 へ移行する（[FR-009] が `is_key_col_unresolved` 不備フラグを検出して異常終了する。[ADR-SRS-011](decisions/ADR-SRS-011-delete-zone-polygon.md) 参照）
  - 詳細・設計判断: [ADR-SRS-004](decisions/ADR-SRS-004-level14-max-pooling-isolated-peaks.md)
```
