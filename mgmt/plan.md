# 計画: SRS §4.4 spec-panel 仕様検討指摘①②の対応

## Context

SRS §4.4（地形解析エンジン）に対する spec-panel レビュー（`mgmt/spec-findings/2026-06-30_1538_SRS-4.4.md`）の
セクション1「仕様検討・判断が必要な指摘」のうち以下2件について設計を確定し、SRS と ADR に反映する。

**指摘① FR-014 無効パターンスキップの判定根拠が曖昧**
現行 SRS 行511の「それまでに解析済みのどの範囲と比べても1枚も増えない配置」という記述は
メカニズムが未定義。設計確定内容：解析識別子をファイル名に含む「解析済みウィンドウメッシュ集合」
ファイル（`<解析識別子>.meshset`）を FR-004/FR-014 が書き出し、FR-014 は各コーナー試行前に
全蓄積ファイルを読んで「候補ウィンドウの存在メッシュコード集合 ⊆ 蓄積済み単一ファイルのメッシュコード集合」
（複数ファイルの和集合ではなく単一ファイルとの部分集合判定）ならスキップする。
解析対象メッシュ範囲情報は内部トランザクションのまま変更なし。

**指摘② FR-016 delete判定ゾーンの安全性根拠が未記述**
`key_col_resolved=false` のピークでも上限キャップで過大化しないと書かれているが、
「低プロミネンスのピークが実際に申請判断へ影響するか」の根拠が不足。
設計確定内容：2分岐で明示（①FR-008最終フィルタで除外→FR-009が参照しない、
②N=6でも未解決→FR-009の不備ゲートで異常終了）。

## タスク一覧

### T1: ADR-SRS-046 新規作成（Sonnet）

ファイル: `docs/decisions/ADR-SRS-046-analyzed-window-meshset-skip.md`

内容骨格:

- **状態**: 採用・未実装 / **決定日**: 2026-06-30
- **Context**: FR-014 無効パターンスキップの実現方法として「それまでに解析済みのどの範囲と
  比べても1枚も増えない」という概念を機械的に実現する手段が未定義だった
- **Decision**:
  - 新規内部データ「解析済みウィンドウメッシュ集合」（`<解析識別子>.meshset`）を導入
  - 中身: そのウィンドウの「存在メッシュコード（日本全土１次メッシュコードリスト内のもの）」のソート済みリスト
  - FR-004 は 3×3 解析完了後に書き出す。FR-014 は各コーナーパターン解析完了後に書き出す
  - スキップ判定: 候補ウィンドウの存在メッシュコード集合 ⊆ 蓄積済み単一ファイルのメッシュコード集合
    （単一ファイルとの部分集合判定であり、複数ファイルの和集合との比較ではない）
  - 解析対象メッシュ範囲情報（ピクセル位置対応を含む）は内部トランザクションのまま変更なし。
    新ファイルにはメッシュコード集合のみを含む（ピクセル位置対応は含まない）
  - 物理ファイル形式・保存先パスは HLD で定義する
- **Alternatives**:
  - A. 実行時に全 per-mesh CSV ファイル名をスキャンしてメッシュコード集合を再構成する案
    → CSV ファイル名にはメッシュコード情報が含まれるが、コーナー配置ごとのメッシュ集合を
    全 CSV から再構成するのはコスト高・誤りやすい。却下
  - B. 和集合との比較（全蓄積ファイルのメッシュコードの和集合 ⊇ 候補集合ならスキップ）
    → 過積極スキップになる（A ∪ B で候補が包含されても、単一の蓄積解析が候補を包含していない
    ならば新たな情報が得られる可能性がある）。却下
- **Consequences**:
  - FR-004/FR-014 出力テーブルに新ファイル行が追加される
  - FR-014 入力テーブルに新ファイル行が追加される（全蓄積ファイルを読む）
  - §8.1 内部データ一覧に No. 13 として追加される
  - 物理形式（拡張子・行フォーマット）は HLD が定義する
