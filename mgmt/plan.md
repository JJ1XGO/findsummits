# SRS §12 要求追跡マトリクス トレーサビリティ整合修正

## Context

`docs/20_SRS.md` §12「要求追跡マトリクス」の spec-panel レビュー（記録: `mgmt/spec-findings/2026-06-29_1948_SRS-§12.md`）で、各 FR 本文の「対応 UR」とマトリクスの ✅ が複数箇所で乖離していることが判明した。トレーサビリティがマトリクス単独で追えず、特に FR-021 はエビデンス ZIP への出典メタデータ埋め込み（UR-011）が追跡不能になっている。

根本原因は「✅ が何を意味するか」の判定基準が未定義なこと。ユーザー合意により **解釈A（直接寄与基準）** を採用する: ✅ は当該 FR/NFR が UR の実現に直接寄与する（成果物生成・品質保証・入力データ供給・主目的としての制御）ことを示し、実行順序制御や前提依存などの間接依存は対象外（§3.3 が担う）とする。この基準では既存 ✅ はおおむね追認され、FR-023=UR-007 も変更不要。残作業は基準の明文化と、本文⇔マトリクスの整合修正に収束する（ただし UR-014 列はセルフレビューの結果、FR-019 への一本化を伴う。下記 T3 参照）。

対象は `docs/20_SRS.md` のみ（URD に UR→FR 対応表は無く、波及は SRS 内で完結することを確認済み）。

## タスク（すべて `docs/20_SRS.md`・モデル: Sonnet）

機械的なドキュメント整合修正のため全タスク Sonnet。

- 該当: §12 冒頭の説明文（「✅ はその FR/NFR が該当 UR の実現に寄与することを示す。UR-009 は削除済みのため列から除外。」）
- 追記内容:
  - ✅ の判定基準（直接寄与のみ。間接依存は §3.3 のフェーズ配置・処理フローで表現する旨）
  - FR-010 が ADR-SRS-028 により削除済みのため行から除外している旨（UR-009 と同様の欠番注記）
- FR-023 行の ✅ は基準に照らし現状維持（UR-007 のみ）

### T3: UR-014 のマトリクス✅を FR-019 に一本化（セクション2 中・セルフレビュー反映）

- 背景: UR-014（ビューア対話応答性）を実現する機能要件は、マーカー描画方式を定義する FR-019（SRS l.1192「マーカーはクライアント側で描画」）。FR-013/FR-020 は生成 FR で応答性ロジックを持たず FR-019 に委譲する。解釈A（直接寄与）に従い UR-014 列を FR-019＋NFR-010 に整理する
- FR-019「対応 UR」行（現状 UR-006・UR-011）に `UR-014` を追加（他 FR と同じ `10_URD.md` アンカーリンク形式で記載）
- §12 マトリクスの FR-019 / UR-014 セルに ✅ を追加
- §12 マトリクスの FR-020 / UR-014 セルの既存 ✅ を削除
- FR-013・FR-020 本文の「対応 UR」は変更しない（UR-014 を追加しない）
- NFR-010 本文の名指し（「HTML ビューア（FR-013・FR-020）のマーカー描画に適用」）は、性能目標の**成果物適用範囲**を示す記述として維持する（マトリクスの ✅＝実現主体とは別レイヤー。描画方式の定義主体が FR-019 である旨は SRS l.1192 で既に参照済み）
- 結果: UR-014 列の ✅ は FR-019・NFR-010 の2つ
