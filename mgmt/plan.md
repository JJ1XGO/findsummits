# FR-022 レビュー反映: FR-022 純化・FR-023 新設・N 扱い再設計・phase 番号統一

## Context（なぜやるか）

FR-022（コル充足判定）レビューで、判定 FR が「N エスカレーションループ・FR-014 呼び出し・FR-008 再実行・陸地最高峰の海面確定」まで抱えており、(1) 判定とオーケストレーションの混在、(2) N の前段/窓サイズ混線（オフバイワン曖昧さ）、(3) 陸地最高峰 override がループ内 FR-008 再統合で消失するバグ、を確認した。あわせて 3.3.1 マトリクスと 3.3.2 俯瞰図/FR 本文で phase 番号（フェーズ3 が「広域」と「統合・判定」の二義）が食い違っていた。

本作業はこれらを SRS・ADR に反映する**ドキュメント変更**（specs-first。コード追従は別 todo）。

## 確定した設計判断（ユーザー合意済み）

1. **指摘1（陸地最高峰 override 永続化）= 案B**: 陸地最高峰（富士山・旭岳・中岳）の海面確定（`key_col_resolved=true`・Key コル=0m）は **FR-008（merge.py）が merged_peak.csv 生成時に毎回適用**する。再統合で消えない。FR-022/FR-023 は特別扱いを持たない。
2. **指摘2（ループ混在・N 曖昧）**:
   - **FR-022 を純粋判定に純化**（入力 merged_peak.csv → 出力「未確定ピーク座標リスト＋未確定有無」。N 計算・+1・FR-014 呼び出しを持たない）。
   - **新 FR-023「解析パイプライン制御」**（shell・自動ループ）が Phase 2/3/4 を統括。**単一の N カウンタを FR-023 のみが保持**。
   - **N＝ウィンドウサイズ**（3=Phase2 / 4・5・6=Phase3）。FR-014 へ **N を明示引数**で渡す。**ファイル名から N を導出する旧方式（データ辞書 L421）は廃止**。
   - 未確定リストは **生成段階 N タグ**（`key_col_unresolved_peaks-<N>.csv`。`-3`=3×3 後に残った分）。**観測用ラベルで制御には使わない**。
   - ループ: `N=3: FR-004一括→FR-008→FR-022→peaks-3` → 非空&N<6 なら `FR-014(N=4, peaks-3)→FR-008→FR-022→peaks-4` → … `N=6` まで。空→Phase4／N=6残存→Phase4（FR-009 が is_key_col_unresolved で異常終了）。
3. **指摘3**: FR-018 欠落は FR-023 が「FR-008＋FR-018 を呼ぶ」と明記して自動解消。
4. **指摘4**: merged_peak.csv の書き手は FR-008 単独のまま（案B で自動解消）。
5. **指摘5**: FR-022「フェーズ4 移行可否を決める」→「未確定の有無を報告」へ表現修正。
6. **指摘6**: FR-009 入力「全ピーク key_col_resolved=true が前提」→「期待。不備は不備フラグで後続へ引き継ぐ」へ整理。
7. **指摘7**: 陸地最高峰リストは FR-008 入力。分類を **ユーザー入力(7.1.4) → 内部データ(7.2)** へ移動（日本全土１次メッシュコードリストと同性質）。
8. **phase 番号統一**: 3.3.1 マトリクスが正。`フェーズ2-1→2`／`フェーズ2-2→3`／統合・判定は番号なし（Phase2 末尾＋Phase3 内・参照は「統合時(FR-008)」へ）／フェーズ1/4/5 は不変。
9. **FR-023 配置**: 新 4.3（現 4.3 地形解析エンジン〜4.6 を 4.4〜4.7 へ繰り下げ）。
