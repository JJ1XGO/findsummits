# ISSUE-090 第2回レビュー反映計画（FR-014 広域結合解析 + FR-022 是正）

## Context

SRS FR-014（広域結合解析オーケストレーション）の第1回レビュー反映（コミット 0c36338）に対し、
本セッションで第2回レビューを実施。「Fable の判断で直した点」4 件と持ち越し論点「解析範囲サイズ N の種別」を
ユーザーと個別議論し、全件の結論が確定した。さらに議論の過程で**陸地最高峰（富士山等）の仕様ギャップ**が
発見され、その対策（海面確定規則 + 既知リスト）も確定した。本計画はこれらを SRS / ADR / トラッカーに反映する。

## ユーザーと確定した事項

### A. 解析範囲サイズ N の種別・抽出（持ち越し論点）
- FR-022 は N 段階ごとにコル未確定ピーク座標リストを **`key_col_unresolved_peaks-<N>.csv`** として
  ファイル出力する（N = 解析済み段階。3×3 後は `-3`、4×4 後は `-4`）
- **N の抽出は FR-022 が担う**: 自ファイル名の N + 1 を算出して FR-014 に渡す
  （エスカレーションループはシェル実装想定・変数渡し）
- FR-014 入力「解析範囲サイズ N」の種別: ユーザー入力 → **内部トランザクション**
- データ辞書 2.2.1 の「解析範囲サイズ N」行は**削除**（ユーザーが調整できる項目ではない）

### B. 陸地最高峰の扱い（新規仕様判断・本セッションで発見したギャップ）
- 現行定義では陸地最高峰（コルが原理的に存在しない）が永遠に未確定 → FR-009 異常終了する欠陥
- **海面確定規則を FR-006 に新設**: 山塊グループが範囲端（人工 1px 海面ボーダー）に接触せず
  flood 完結 → Key コル = 海面(0m)・プロミネンス = 標高・`key_col_resolved=true`
  （島の最高峰は 3×3 または広域解析で自動確定）
- **陸地最高峰リストを新設**（ユーザー入力・パラメータファイル・7.1 追加）:
  どのウィンドウでも陸地全体を囲えない **富士山（本州）・旭岳（北海道）・中岳=九重（九州）の 3 件**。
  FR-022 がリスト一致ピーク（座標近傍一致・許容距離は HLD）を広域対象から除外し海面確定に更新
- 検証ポイント（実装後）: 石鎚山（四国）が実データで 3×3 確定するか。しなければリストに追加

### C. Fable 判断 4 件の個別レビュー結果
1. **①無効パターンスキップ**: 承認 + **一般化**。
   「**それまでに解析済みのどの範囲（3×3 と既解析の広域窓）と比べても存在メッシュが 1 枚も増えない
   配置はスキップ**」に文言変更（N 段階間の重複スキップもカバー）
2. **②所属メッシュ単位グルーピング**: 承認（現行記載のまま）
3. **③L15 座標維持**: 承認 + 追記 2 点:
   - FR-007 対象ピーク絞り込みの一致判定方法を明記（緯度経度を L15 タイル座標に変換して比較・
     FR-008 の重複排除と同一規則）
   - max pooling 同値時の採用ピクセル決定は決定的とする旨（具体規則は HLD/LLD）
4. **④異常系**: **強化**。
   - 3×3 相当範囲タイルゼロ → エラー中止（既存）
   - **追加: ウィンドウ（矩形）内の存在メッシュにローカルタイルが 1 枚も無い → エラー中止**
     （prefetch 漏れ検出 + 海面確定規則の誤発動防止。該当メッシュを表示し prefetch 再実行を案内）
   - NODATA 続行が許されるのは「リスト外メッシュ（本物の海・国外）」と
     「存在メッシュ内の部分的欠損（地理院未整備）」のみ
   - bounding box（最小矩形）解析の記載は維持（矩形=外側を切る規則、④=矩形内の欠損の扱い、で役割分担）
