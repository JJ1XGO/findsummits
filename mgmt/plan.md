# FR-017 N03 行政区域前処理（データ準備） SRS レビューと書き直し計画

## Context

FR-017 の現状記述（docs/02_SRS.md 272-298 行）は、レビューしたユーザー本人が「説明を読んでも何をしようとしているか理解できない」と評価するレベルで不明瞭。

主な問題:
- **なぜ前処理が必要なのか**（生データのままで使えない理由）が書かれていない
- **何から何へどう生成するのか**（生成ロジック）が完全に欠落
- 出力テーブル「形式」セルに件数情報のみで、生成方法・派生関係が読み取れない
- 「北方領土除外タイルリストの判定基準」が表現として読めない（タイル単位除外の意味と FR-003 との役割分担が暗黙）
- 入力分類「外部I/F」が誤読を招く（自動取得すると読める。実態は手動配置）
- 入力ファイル形式が ZIP であることが SRS から見えない
- 「47都道府県+14振興局=61地域」が論理矛盾（北海道二重カウント）
- ファイルパス内変数 `{n03_year}` が ADR-SRS-014 規約 4 と整合しない

派生して、ADR-URD-005「タイル単位除外で十分な精度が得られる理由」の論証が「本土を誤除外しない」方向にしか向いておらず、「北方領土の取り逃しなし」の根拠が欠けている疑念がある。

本計画は FR-017 の SRS 記述を抜本的に書き直し、関連する 6.15・2.2.1・7.2・7.2.1・ADR-URD-005 まで整合させる。

## 書き直し案

### A. FR-017 セクション本文（提案）

```markdown
#### FR-017: N03 行政区域前処理（データ準備）

- **対応 UR**: [UR-001](01_URD.md#ur-001), [UR-003](01_URD.md#ur-003), [UR-004](01_URD.md#ur-004)
- **概要**: 国土数値情報の市区町村単位の行政区域 GeoJSON（約12万ポリゴン）から、
  後段 FR が利用する 3 種類の派生データを生成する初回限定のデータ準備処理。
  なぜ前処理が必要か:
  - 生データは約 580MB と大きく、突合処理（FR-009）が毎回読み込むには重い
  - SOTA エリアコード（TK・KS 等）は市区町村単位では付与できないため、46 都府県＋
    14 北海道振興局＝ 60 地域単位に集約して各地域へ接頭辞・コードを紐付ける必要がある
  - 北方領土（[ADR-URD-005] 参照）はピーク検出段階（FR-003）で除外したいが、
    C エンジンに GIS ライブラリを持ち込まずに済むよう、除外対象タイルのリストを事前生成する

**入力**:

| データ名 | 種別 | 必須/任意 | デフォルト（任意時） | 備考 |
|---|---|---|---|---|
| N03 行政区域 ZIP | ユーザ入力 | 必須 | — | [7.1.X 参照] |

**出力**:

| データ名 | 種別 | 形式 | 備考 |
|---|---|---|---|
| N03 前処理済み地域 GeoJSON | 内部データ | GeoJSON（60 地域） | [FR-009] での SOTA エリアコード自動付与に使用 |
| N03 前処理済み市区町村 GeoJSON | 内部データ | GeoJSON（約 2,000 市区町村） | [FR-009] での所在地（市区町村名）取得に使用 |
| 北方領土除外タイルリスト | 内部データ | テキスト | [FR-003] での NODATA マスクに使用 |

**説明**:

- **実行タイミング**: 初回のみ。`$DATA_DIR/ref/` 配下に N03 ZIP が存在し、かつ
  対応する出力ファイル群が未生成の場合に起動する
- **入力 ZIP の検出**: `$DATA_DIR/ref/` を `N03-(\d{8})_GML\.zip` のパターンで走査し、
  YYYYMMDD が最大の ZIP を採用する。0 件ならエラー終了。複数候補がある場合は最新を採用し、
  採用 ZIP 名・YYYYMMDD・サイズをログに記録する
- **ZIP 内ファイルの取り出し**: ZIP 内の `N03-{YYYYMMDD}.geojson`（市区町村版）のみを
  一時ディレクトリに展開して読み込み対象とする。処理完了後は展開ファイルを削除する
  （`$DATA_DIR/ref/` 直下に解凍ファイルを残さない）。`_prefecture.geojson`・
  Shapefile・XML 等は展開対象外
- **生成 1: 地域 GeoJSON（60 地域）**:
  - 市区町村ポリゴンを N03_001（都道府県名）でグループ化
  - 北海道のみ N03_002（振興局名）で再グループ化
  - 各グループ内ポリゴンを dissolve（隣接ポリゴンをマージ）して 1 地域 1 ポリゴンに集約
  - 各地域へ SOTA エリア接頭辞（JA / JA5 / JA6 / JA8）と area_code（TK・IS 等）を付与
  - 結果: 46 都府県 + 14 振興局 = 60 ポリゴン
- **生成 2: 市区町村 GeoJSON（約 2,000 件）**:
  - 市区町村ポリゴンをそのまま流用
  - プロパティを `prefecture`・`municipality`・`code`（N03_007）の 3 つに最小化
- **生成 3: 北方領土除外タイルリスト**:
  - N03_007（行政区域コード）が 01696〜01701 に一致するポリゴン
    （択捉・国後・色丹の 6 村。詳細: [ADR-URD-005]）を抽出
  - 各ポリゴンの bounding box 内のズームレベル 15 Web Mercator タイル
    （地理的に約 1.2km 四方）について、タイル中心点がポリゴン内に含まれるタイルを列挙
  - x y 整数ペアの 1 行 1 タイル形式のテキストで出力
  - **このリストの使われ方**: FR-017 はリストを生成するだけ。実際の除外は
    FR-003（C エンジン側）がリストを読み込み、該当タイルの全ピクセルを
    NODATA(-9999m) として扱うことで実現する
- **フォールバック（後段 FR の動作）**:
  - 地域 GeoJSON が未生成の場合: FR-009 は SOTA エリアコード判定をスキップし、
    地域不明を示す仮サミットコード（`ZZ/ZZ-A01` 形式）を付与（詳細: [FR-009]）
  - 北方領土除外タイルリストが未生成の場合: FR-003 は北方領土タイルの NODATA 化をスキップ
- **出典**: [`ref/SOURCES.md`](../ref/SOURCES.md)（国土数値情報 N03 行政区域）
```

書き直しのポイント:
- **概要**で「なぜ必要か」を 3 つの目的に分けて明示
- **入力テーブル**を ZIP 1 項目に簡素化（ユーザ入力種別）
- **出力テーブル**の「形式」セルは形式（GeoJSON / テキスト）と件数のみ、用途は備考へ
- **説明**で「ZIP 検出」「ZIP 内ファイル取り出し」「生成 1/2/3」「フォールバック」と段階別に整理
- **「タイル中心点判定」を読める文章に再構成**（タイル ≒ 1.2km 四方・FR-003 が NODATA 化を担当）
- 実装詳細（コード値 01696〜01701・正規表現パターン）は SRS にも残す（仕様判断としての意味があるため）

### C. ADR の補強

#### C-1. ADR-URD-005「タイル単位除外で十分な精度が得られる理由」

現状の論証は「本土を誤除外しない」のみ。以下を追加:

- **取り逃しタイルのリスク評価**: ポリゴン中心点判定では、ポリゴン端の海岸線付近のタイル
  （中心点が海側にずれる）が除外リストに含まれない可能性がある。論理的には:
  - 取り逃しタイル ≒ 海岸線タイル ≒ 標高が低い領域
  - サミット検出はプロミネンス 150m 以上のピークが対象
  - よって取り逃しが起きてもサミット検出結果に影響しない可能性が高い
- 上記論理が成立するかは実データ検証が必要。本タスクのスコープ外として
  **別タスク（新規 ISSUE）に切り出す**。検証内容:
  - N03 から北方領土ポリゴンを抽出
  - 北方領土領域の DEM タイル（dem5/dem10）でピーク検出
  - プロミネンス 150m 以上のピークがポリゴン端付近に存在するか確認
  - 存在しなければ ADR の論証として確定。存在する場合は buffer 処理を導入

本タスクでは ADR-URD-005 に「取り逃しリスクの考察」と「実データ検証は別タスクに切り出した旨」を追記するに留める。

#### C-2. ADR-SRS-014 規約 4 との整合性

- 6.15・7.2 にあるファイルパス内変数 `{n03_year}` を HLD へ追い出すかの判断
- 「年版」概念を SRS から廃止する場合、N03 関連の `{n03_year}` も同時に廃止できる可能性
- 7.2.1 の出力ファイル名規則を SRS に残すか HLD へ移すかは規約 4 解釈次第

1. **SRS 内部リンク整合性**: 6.15 削除・7.1 追加に伴う目次・本文中の参照リンクを全件確認
   ```bash
   grep -n "6\.15\|615" /workspace/docs/02_SRS.md
   grep -n "fr-017" /workspace/docs/02_SRS.md
   ```
2. **「61」「47都道府県」表記の残存チェック**:
   ```bash
   grep -n "61[地域]\|47[都]" /workspace/docs/02_SRS.md /workspace/docs/decisions/*.md
   ```
3. **`{n03_year}` 変数の扱い統一**: HLD へ追い出すなら全件削除、SRS に残すなら命名統一を確認
   ```bash
   grep -n "{n03_year}" /workspace/docs/02_SRS.md /workspace/docs/decisions/*.md
   ```
4. **ADR-URD-005 取り逃し検証用の実データ確認**（C-1 検証）:
   - venv/bin/python3 で N03 から北方領土ポリゴン抽出
   - 既存 prefetch 済みタイルがあれば該当領域のピーク検出
   - 残存リスクの定量化
5. **マインドレビュー**: 「説明」を読み返して、「読み手が何から何へどう生成するかを誤解なく理解できるか」を確認
