# SRS データ辞書: 位置移動と網羅性向上、FR 名称統一

## Context（背景）

ADR-SRS-014 で SRS の機能要件テンプレート化とデータ辞書（3.4）導入を行ったが、ユーザー指摘により以下の問題が判明した:

1. **配置の不自然さ**: データ辞書（3.4）は「3. システムアーキテクチャ概要」配下にあるが、内容的には用語定義の延長であり、「2. 用語定義」配下に置く方が文書構造として自然。
2. **網羅性不足**: 3.4.2「入出力データ」は **ユーザー成果物・設定項目中心**で、FR 間で受け渡される中間データ群（結合画像・標高ピクセル・山塊グループ・merged_peak.csv・北方領土除外タイルリスト等）が登録されていない。
3. **データ辞書原則の違反**: 3.4 冒頭の「本セクションで定義した名称を使用すること」が守られていない。テンプレ移行（昨日）の時点でデータ辞書がまだ確定していなかったため、各 FR が独自命名で穴埋めしてしまった。
4. **運用ルール欠落**: ADR-SRS-014 に「辞書未定義データを発見した場合の取扱い」（追加すべきか別名で良いか）規定が無い。

仕様優先原則のもと、SRS を確定品質まで仕上げる必要がある。HLD 移行前にこれを整理する。

## ゴール

- データ辞書を「2. 用語定義」配下に移動
- 中間データ・最終成果物まで網羅した辞書に拡張
- 全 21 FR の入出力テーブル「データ名」セルを辞書名と一致させる
- ADR-SRS-014 に「辞書未定義データの扱い」運用ルールを追記

## ADR-SRS-014 への規約追記（規約 5 新設）

```markdown
### 規約 5: データ辞書の拡張規則

FR を記述する際にデータ辞書（2.2 節）に未定義のデータ項目を発見した場合は、
**まず辞書に追加してから** FR 側で引用すること。

- **辞書登録の粒度**:
  - 単位は「ユーザーが認識できる粒度（成果物単位・主要中間ファイル単位）」とする
  - ピクセル単位のバイト構造・配列構造等の詳細は HLD に委ねる
- **辞書項目のカテゴリ**: A. 外部入力データ / B. FR 間中間データ / C. 最終成果物 のいずれかに分類する
- **派生形の補語**: 「リスト」「単一ピクセル」「ローカルキャッシュ済」等の派生形補語は
  辞書側には書かず、FR の入出力テーブル「データ名」セルで本体名に括弧書きで補う
  （例: 辞書「1次メッシュコード」→ FR で「1次メッシュコード（リスト）」可）
- **`new` データ項目の例外**: 一時的なメモリ上構造で他 FR との受け渡しに使われない場合は
  辞書登録を省略してよい（ただし FR 内で完結することを明示する）
```
