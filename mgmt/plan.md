# FR-019 spec-panel 指摘対応 計画

## Context

spec-panel スキルで FR-019（HTML ビューア機能仕様）をレビューし、8 件の指摘を抽出した。
ユーザー判断で **指摘② は「名称修正」記述の削除**（名称修正・名称変更は行わない方針のため作業漏れ扱い）に変更、
他はレビュー推奨対応どおり実施する。本件は `docs/20_SRS.md` の整合性修正であり、コードは触らない
（仕様優先原則・ドキュメント実装整合性原則の範囲）。目的は ADR-SRS-038（FR 入出力テーブルの外部I/F 網羅性）と
UR-011（帰属表示）の要件を FR-019 正本および台帳（§6.1・§9）で完結させること。

## 対象ファイル

- `docs/20_SRS.md`（全修正の対象）

## 修正タスク（すべて Sonnet）

### タスク1: 指摘① UR-011「加工して作成」明示の追加（重要度: 高）

- **FR-019 行1204**: 帰属表示の段落末尾に「加工して作成」の旨の明示を追記する。
  UR-011 は「出典 + 『加工して作成』の旨の明示」を要求。現状 FR-019 は出典のみで「加工して作成」が欠落。
  FR-020 行1129 はこれを「FR-019 と同等の地図帰属表示（…＋『加工して作成』の旨の明示）」として参照しているため正本側を補完する。
- **§6.2.6 作業用 HTML ビューア（行1554-1563）**: 帰属表示行が無い（§6.2.8 公開用 行1590 にはある）。
  6.2.8 と同等の「帰属表示」行を 1 行追加し、`© 国土地理院` 常時表示 + OSM/OpenTopoMap 併記 +「加工して作成」明示 + FR-019 参照を記載。

### タスク2: 指摘② 「名称修正」記述の削除（重要度: 中・方針変更）

- 「名称修正」は採用しない概念。残存 3 箇所から削除する:
  - **FR-020 行1130**: 「（山岳名JP/EN・rationale 編集値・名称修正）」→「（山岳名JP/EN・rationale 編集値）」
  - **FR-019 行1219**: 「入力した山岳名・rationale 編集内容・名称修正は…」→「入力した山岳名・rationale 編集内容は…」
  - **FR-019 行1227**: 「（山岳名JP/EN・rationale 編集値・名称修正）」→「（山岳名JP/EN・rationale 編集値）」
- FR-021 行1362 は既に「名称修正」を含まない（山岳名JP/EN・rationale 編集値のみ）ため、削除後に全 FR で表現が揃う。

### タスク3: 指摘③ §6.1 外部I/F一覧の台帳逆引き漏れ補完（重要度: 中）

- ADR-SRS-038 Decision 2 の集約原則に従い、実行時タイルの使用 FR は **FR-019 に集約**して記載する（FR-020 は記載しない）。
- **No.10 地理院標高タイル（行1471）**: 使用 FR に FR-019 を追記（等高線オーバーレイの実行時取得）。
- **背景タイルのエントリを新規追加**: 「背景タイル（国土地理院標準地図・淡色地図・OSM・OpenTopoMap）｜入力｜PNG｜FR-019｜実行時取得・基図。出典: `ref/SOURCES.md`」。
- **地理院基準点タイルのエントリを新規追加**: 「地理院基準点タイル｜入力｜GeoJSON（ベクトルタイル）｜FR-019｜基準点レイヤー ON 時に実行時取得。出典: `ref/SOURCES.md`」。
- **詳細仕様の粒度**: 新規 2 エントリの補足欄は `ref/SOURCES.md` 参照に留め、§6.2 詳細仕様の新設はしない（過剰回避。実行時取得タイルの規約は SOURCES.md が正本）。
  既存 No.10（§6.2.10 参照）とは粒度が異なるが、解析入力タイル（No.10）とビューア実行時タイルの性質差として許容する。

### タスク4: 指摘④ §9 外部システム依存関係の補完（重要度: 中）

- **§9 行1755 国土地理院 標高タイル配信**: 用途に「HTML ビューアの背景地図（標準地図・淡色地図）・基準点レイヤー（FR-019）」を追記、
  または同ドメイン（`cyberjapandata.gsi.go.jp`）の配信として用途を一般化する。
- **§9 行1758 地図タイル配信（OSM・OpenTopoMap）**: そのまま（地理院は上行に統合）。
- **§9 行1759 CDN（Leaflet・SheetJS）**: JSZip を追記（FR-021/FR-019 で ZIP 生成に使用）。

### タスク5: 指摘⑤ FR-019 出力テーブルに localStorage 追記（重要度: 中）

- **FR-019 出力テーブル（行1156-1159）**: 行追加「localStorage 編集内容｜内部データ｜JSON（ブラウザ localStorage）｜詳細は §8.2.2 参照」。
  §8.1 No.12 が生成 FR=FR-019 と明記しており、生成責任を出力テーブルに反映する。

### タスク6: 指摘⑥ FR-019 入力テーブルに localStorage 追記（重要度: 低）

- **FR-019 入力テーブル（行1148-1152）**: 行追加「localStorage 編集内容｜内部データ｜任意｜初期値（FR-009 自動生成テンプレート）｜再訪時に読み込む。未編集（localStorage 空）の場合は初期値を使用」。
  FR-020 行1116・FR-021 行1339 と粒度を揃える。

### タスク7: 指摘⑦ localStorage 引き継ぎ「引き継がない」挙動の明示（重要度: 低）

- **FR-019 行1221**: 「引き継ぎますか？」の選択肢のうち **「引き継がない」を選んだ場合は、前回 localStorage を破棄せず保持したまま、今回の `generated_at` キーで初期値（FR-009 自動生成テンプレート）から開始する** ことを明示する。前回データの削除は行わない（確認なしでユーザーの入力成果を消す事故を避けるため。破棄が必要な場合の扱い・容量上限超過時の扱いは行1219 のとおり HLD に委ねる）。

### タスク8: 指摘⑧ rationale UI の category=review 扱いの明示（重要度: 低）

- **FR-019 行1213-1217 rationale 編集 UI**: `category=review`（要確認・孤立既存サミット）は **rationale UI 不要**（申請対象外。`no_change` と同様に XLSX 行を出力しないため）を 1 行追記する。
  山岳名入力 UI（行1208-1211）は既に add 系のみ対象で review を含まないため追記不要。

## 検証

1. `make lint`（lint-md = pymarkdown + `scripts/lint_docs.py`）で警告ゼロを確認。
2. `grep -n "名称修正" docs/20_SRS.md` で残存ゼロを確認（タスク2）。
3. `grep -n "加工して作成" docs/20_SRS.md` で FR-019・§6.2.6 への追加を確認（タスク1）。
4. §6.1 台帳・FR-019 入出力テーブル・§8.1 No.12 の相互参照が双方向で揃うことを目視確認（ADR-SRS-038 の俯瞰点完全性）。
5. 完了後そのターン内で Conventional Commits 形式でコミット（プロジェクト CLAUDE.md「ドキュメント更新は当該ターンで commit」）。push は別途指示まで行わない。
