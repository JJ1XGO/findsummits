# SRS ボトムアップ spec-panel レビュー進捗

- 対象: `docs/20_SRS.md`
- 開始日: 2026-07-06
- 方式:
  - **Tier1（最下層）**: §x.y.z 粒度のセクション + FR-xxx/NFR-xxx 個別要件
  - **Tier2（中間ロールアップ）**: §x.y 粒度のセクション（Tier1が全周回で指摘ゼロになってから着手）
  - **Tier3（上位ロールアップ）**: §x 粒度のセクション（Tier2が全周回で指摘ゼロになってから着手）
  - **Tier4（全体通しレビュー）**: `docs/20_SRS.md` 全体（Tier3が全周回で指摘ゼロになってから着手）
  - **Tier分類は記法上の深さで機械的に決める（2026-07-07改訂）**: 子セクションの有無に関わらず、`§x` は Tier3、`§x.y` は Tier2、`§x.y.z` は Tier1。子を持たない「葉」セクション（例: §1・§9〜§12 は `§x` なのでTier3、§2.1・§3.1・§3.2・§6.1・§7.1・§8.1 は `§x.y` なのでTier2）も例外なくこの規則に従う
  - **収束ループ（2026-07-07改訂）**: 各Tierは「そのTierの全項目を一通りレビューする」周回を単位とする。ある周回で1件でも指摘が発生した場合、その周回完了後に**同じTierの全項目を最初から再度レビューする**（次の周回。指摘が出た項目・関連項目だけの再レビューではなく全項目が対象）。ある周回で指摘が完全にゼロだった場合のみ、次のTierへ進む
  - **指摘の適用方針（2026-07-07改訂）**: spec-panelの指摘（作業実行・仕様検討を問わず）は原則すべて適用する。ただし「仕様検討」種別で仕様判断に詰まる場合は、まずFable（不可時Opus）サブエージェントへ見解を確認し、事実確認を行った上で適用する。上位モデルでも判断できない場合に限りユーザーに判断を委ねる
- 完了条件: Tier4のある周回で指摘ゼロ → `docs/20_SRS.md` ヘッダーの「ステータス」を `確定` に更新

凡例: ステータス = 未着手／対応中／完了。「関連spec-findings」は `mgmt/spec-findings/` 配下のファイル名（拡張子略）。各Tierの表は周回ごとに区切る（過去周回の表は履歴として保持し上書きしない）。

**2026-07-07 再分類**: 当初Tier1に含めていた §1・§2.1・§3.1・§3.2・§6.1・§7.1・§8.1・§9・§10・§11・§12（子セクションを持たない「葉」だが記法上の深さが `§x.y.z` でない11件）を、記法深さベースの原則に従いTier2・Tier3へ移動した。既に完了していた項目（§1・§2.1・§3.1・§3.2・§6.1）はレビュー内容自体の変更ではなく分類の是正のため、ステータス・関連spec-findings・備考をそのまま引き継いだ。
