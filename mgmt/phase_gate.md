# フェーズゲートレビュー

> ステージ本体成果物の確定後・次ステージ本格着手前に、クローズ可否をチェックリストで判定する
> マイルストーンレビュー（工程完了審査 / phase gate review / quality gate 相当）。
> ステージ定義の正は `docs/CLAUDE.md` の採番表（`00_GLOSSARY` 〜 `80_OPS`）を参照し、本ファイルでは
> 再定義しない。個別ステージの成果物品質そのものの管理は `mgmt/srs_review_progress.md`（SRS）や、
> HLD以降は GitHub Issues の進捗トラッキング（親issue「HLD 執筆トラッキング」、内部運用issue参照）
> が担い、本ファイルはステージ間の遷移判定のみを扱う。

## GitHub マイルストーンとの役割分担

ゲートに紐づく `type:設計` issue の束は GitHub マイルストーン（例: 「ゲート3: HLD → LLD」）で
可視化してよい。ただし**判定結果（Go/条件付きGo/No-Go）はマイルストーン側に書かず、本ファイルの
ゲート台帳に一本化する**（二重管理の回避）。マイルストーンの description には本ファイルへの参照を
書くのみとする。将来ゲートのマイルストーンは、そのゲートが近づいた時点で作成し、先行作成しない
（内部運用issue参照）。

## 運用ルール

- **実施者**: 資料作成・観点チェックは Claude、**判定者はユーザー**（Go/条件付きGo/No-Go を最終決定）
- **判定区分**:
  - **Go**: 次ステージへ進んでよい
  - **条件付きGo**: 次ステージ着手は可とするが、明記した条件を次ゲートまでに消化する
  - **No-Go**: 当該ステージへ差し戻し、条件解消後に再ゲート
- **チェック観点**（6項目、すべて記録する）:
  1. **成果物品質**: レビュー収束・確定状況（進捗表の全Tier完了、ステータス「確定」、lint警告ゼロ）
  2. **未解決課題の処置**: 当該ステージ帰属の open 課題・既知乖離の棚卸しと処置（持ち越し理由を明記）
  3. **次ステージ準備**: 進捗管理表・入力成果物・関連 issue 紐づけの整備状況
  4. **体制**: 要員・経験値のリスク評価と軽減策
  5. **リスク管理**: リスク台帳・コンティンジェンシープランの整備状況（見送る場合はその判断を理由付きで記録する）
  6. **総合判定**: 上記1〜5を踏まえた Go/条件付きGo/No-Go 判定
- 各ゲートの記録は追記のみとし、既存ゲートの記録は書き換えない（履歴として保持する）

- HLD執筆はプロジェクトとして初めての本格的なステージ横断設計文書であり、経験値が少ない
- **リスク評価: M（中）**（2026-07-12 Fableサブエージェント諮問・ユーザー承認）。評価対象は軽減策
  適用後の残余リスク。SRSで「初の本格レビュー→確定到達」という同型状況を既に乗り越えた実績があり、
  1名+Claude体制で追加できる実効的な対策はもう残っていないため M が妥当（H は既存策で不十分・新対策が
  必要な場合に留保すべき）

  設計判断で確信が持てない場合は上位モデル（Fable）サブエージェントへ諮問する運用が既に定着、
  `mgmt/hld_progress.md` による FR/NFR/章単位の分割統治で一度に扱う範囲を小さく保つ

### 5. リスク管理
