# Lessons Learned

## アルゴリズム・実装

- **致命的バグ(13b1f72)**: `load_mesh_tile()` でタイル書き込み後に前行を 0 リセットしていた。`calloc` で初期化済みのためリセット不要。タイルを上書きするコードは書く前に「本当に必要か」を確認する。
- **コル検出(c317186)**: Union-Find の `union` 時に `peak_id < 0`（海面コンポーネント）のチェックが抜けていた。海面境界との接触を「コル」として誤検出していた。

## パフォーマンス実績

- **9メッシュ解析時のメモリ使用率（2026-04-24実測）**:
  - 5339（中心メッシュ・最大解析範囲）: 解析範囲61,650枚・イメージサイズ70,146×57,602px・メモリ宣言値15,413MB
  - イメージ書き出し時: max 63%（≒39.5GB）
  - Union-Find解析時: **max 90.8%（≒56.9GB）**　← Opusの見積の2倍以上
  - 62.72GBマシンでスワップなしで完走（ギリギリ）
  - **教訓**: メッシュが中心に近いほど解析範囲が広がり、メモリ使用量が急増する。全国解析では中心付近のメッシュで同様の状況が発生しうる。

## 設計判断

- **DEM1a は不採用**: プロミネンス 150m 判定には DEM5（5m解像度）で十分。DEM1a はデータ量が 25 倍になるが精度向上はほぼない。
- **レベル15→14ダウンサンプリングはmax pooling採用**: プロミネンス計算目的では山頂を保持するmax poolingが適切。キーコルは実際より高く評価されプロミネンスが過小になるが、申請に対して保守的な方向なので許容範囲。NODATAは最大値計算から除外すること。
  - **用途**: 大山・東北の独立峰など、解析範囲内でKeyコルが見つからないピークに対して広域再解析する手段として。
  - **実装方針**: タイルファイルを作るのではなく、レベル15タイルを読み込んで結合する際にmax poolingでレベル14化する。同じメモリで4倍の面積をカバーできる。
  - **実装時の注意点**（漏れチェック）:
    1. **座標変換**: `mesh.c` のタイル座標↔地理座標変換はレベル15前提。レベル14化するとピクセルサイズが2倍になるため変換ロジックの修正が必要。
    2. **col_margin_px**: 現在はレベル15ピクセル単位。レベル14化後は1px=レベル15の2px相当になるため、CSV出力・判定ロジックへの影響を確認すること。
    3. **1pxボーダー**: メッシュ外周の海面ボーダーがレベル14化後は地理的に2倍の幅になる。意図通りか確認すること。
    4. **257×257オーバーラップ**: タイル境界の1pxオーバーラップをmax pooling時にどう扱うか設計が必要。

## 未解決の課題

- **dem10b が存在しないタイルがある**: prefetch しても一部タイルが取得できないケースがある（findsummits 実行時に「dem10b タイル未キャッシュ N 件」警告として現れる）。該当箇所は NODATA 扱いで解析は続行される。terrain PNG では矩形ブロック状の異常（黒や黄緑の格子）として視認できる。

- **terrain PNG に細い水平線が描画されるバグ**: `5239_terrain.png` で確認。タイル境界の接合処理が原因と推測。dem10b 未キャッシュによる矩形ブロックとは別の問題。処理中のため未調査、後回し。

- **タイル取得の最後の数枚が詰まる問題**: NOSIGNAL修正・LOW_SPEED設定を入れたが、それでも最後の1〜数枚が数分単位で止まることがある。原因不明。TIMEOUT/LOW_SPEED_TIMEの値調整、リトライロジックの追加、または直列フォールバック（最後のN枚は1スレッドで確実に処理）などを検討する余地あり。

- **【解決済み】dem10b URL誤設定（2026-04-24修正）**: `prefetch_tiles.py` の `GSI_DEM10B_URL` が `dem10b_png` というサービス名になっていたが、正しくは `dem_png`。参照元: https://maps.gsi.go.jp/development/ichiran.html#dem。修正後 HTTP 200 確認済み。`/data/tiles/14/` に残っていた残骸ファイル（誤URLで取得したエラーXML）は削除済み。次回 prefetch で正しいdem10bタイルが取得される。

## Patterns to Avoid
*避けるべきパターンを記述すること。ファイルの中身を勝手に消さない。

- **【重大】合意済み仕様の無断変更禁止**: ユーザーと合意した仕様（例: 3×3フルメッシュ解析）を、技術的困難を理由に勝手に変更してはならない。変更が必要な場合は必ずユーザーに状況を説明し、両者の合意を得てから変更する。黙って仕様を変えることは重大な技術者倫理違反である。
- **【重大】許可されたパス以外への書き込み禁止**: dangerouslyDisableSandbox: true が要求される様なコマンドを実行してはならない。書き込もうとしたパスが許可されていない場合は、ユーザに理由を説明した上で書き込み可能にして貰う事。プロジェクトで許可された範囲以外のコマンドを実行する事は重大な技術者倫理違反である。
- **【重大】指示されたスコープを超えて先に進まない**: 「〜まで」「〜だけ」と範囲が明示された指示は、その境界で必ず止まる。次のステップが明らかであっても、ユーザーの明示的な指示なしに先へ進んではならない。ユーザーが途中で止める理由（タイミングを自分で決めたい・他に確認したいことがある等）は常に存在しうる。「どうせ次もやるから一緒に」という先読みは禁止。（2026-04-24: 「止める所まで」という指示を無視して再実行まで進めてしまった）
