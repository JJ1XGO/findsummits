# issue #23 決着計画: Rust/C++ 言語選定・階層的 UF 分割の ADR 見直し検討

## Context

issue #23（type:調査）は、調査資料 `docs/decisions/research/rust-cpp-and-scalable-analysis-research.md`
（2026-07-09 相談の整理）を踏まえ、以下 2 点の見直し要否を検討し決着（決定＋ADR/SRS への記録）させるもの。

1. 資料 A〜C（Rust vs C++、Rust での OpenCV、gccrs）を踏まえた `ADR-SRS-010`（C++/OpenCV 移行）の再検討要否
2. 資料 E（階層的 Union-Find 分割）を踏まえた `ADR-SRS-003`（3×3 メッシュ解析）の再検討要否

検討時にユーザーから追加された文脈: **現行実装は v1.0 のプロトタイプであり、将来的には解析処理の
さらなる効率化と、地理院地図の標高表示（DEM1 系データ整備地点ではその値を表示）への追従を考えている。
コードありきではなく URD/SRS を正として、将来の実装切替の可能性まで含めて検討する。**

本計画は spec-panel セルフレビュー済み（指摘記録: `mgmt/spec-findings/2026-07-11_1202_plan-issue23.md`。
作業実行系指摘 12 件を本計画へ反映済み・仕様検討系は該当なし）。

## ユーザー決定（2026-07-11 確定）

1. **将来要件（解析効率化・DEM1a 追従）を URD に明文化する**（「将来スコープ（v2.0 候補）」として。v1.0 要件には影響させない）
2. **ADR-SRS-010: C++ 維持**。Rust を Alternatives に却下理由付きで追記
3. **ADR-SRS-003: v1.0 は 3×3 で確定。階層的 UF 分割を v2.0 の本命候補としてロードマップ記録**し、実現可能性検証を独立 issue 化（本命候補＝将来決定の確定ではなく、実現可能性検証を経て採否を判断する位置づけ）
4. **SRS ボトムアップレビューの再開方法: Tier3 周回1 の差分周回は省略し、本決着の docs 実装後に
   Tier3 周回2（確認用全件周回）から再開**（周回1 実質欠陥 2 件〔§9・§10〕は他章から本文参照なしを
   grep 確認済み。周回2 が URD/GLOSSARY 変更との相互参照確認を兼ねる。Tier1・Tier2 の先例と同型）

### 決定理由の骨子（ADR 追記内容の根拠）

- **言語（C++ 維持）**: 性能は同等で移行動機なし（資料 A）。OpenCV は C++ ネイティブ vs Rust は FFI
  バインディング（ビルド複雑性、資料 B）。将来の解析方式転換も C++ で成立し（Parallel Priority-Flood の
  先行実装 RichDEM は C++）、**言語切替を強制されるシナリオがない**。メモリ安全性の主要な痛点
  （malloc/free）は RAII 限定方針で解消済み。個人開発での borrow checker 学習コスト。gccrs は実用外（資料 C）
- **方式（v1=3×3、v2=分割転換を計画）**: 現行 NFR-002（メモリ）は 3×3 で実測充足済み（NFR-005 処理時間の
  記載は下記タスク7 の注意参照）。3×3 前提は SRS の 7 FR（FR-004/006/008/009/014/016/023）と ADR-SRS-004 に
  織り込み済みで SRS は Tier3 レビュー中・確定間近。前例（Barnes 2016）は連結性問題であり「成分マージ時の
  Key コル特定」が境界マージで正しく保存されるかは未立証（プロトタイプ検証が必要）。一方 **DEM1a 追従
  （データ量 25 倍）ではモノリシック方式（DEM5 で実測 57GB）が成立しない見込みで、将来要件が確定すれば
  方式転換が必要** — 受動的な見送りでなく v2.0 ロードマップとして能動的に記録する

### SRS レビューへの影響（決定 4 の根拠）

本決着で変更されるのは URD・GLOSSARY・ADR のみで **SRS 本文（`docs/20_SRS.md`）は無変更**。
よって Tier1/Tier2 に戻る必要はない。ただし Tier3 の照合には URD/GLOSSARY を突合先にした項目があるため
（§1 目的・範囲、§2 用語定義、§10 制約・前提条件〔DEM1a 不採用・ADR-SRS-002 参照〕、§11 スコープ外
〔URD §6 の 11 項目と完全一致照合〕）、周回2（全件）でこれらの相互参照確認を明示的に含める。
**Tier3 周回2 の実施自体は本計画のスコープ外**（本計画は再開準備＝進捗ファイル更新まで）。
