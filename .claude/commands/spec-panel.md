# 多視点パネルレビュー

指定された仕様文書（URD/SRS/HLD/LLD/ADR の章・FR 番号など）を、以下の4視点で
順にレビューし、指摘を一覧化する。引数で対象を受け取る（例: `/spec-panel FR-013`）。

## 前提ルール（厳守）
- 仕様優先原則: コードを正として参照しない。仕様書の内容を正とする
- 自動 spawn 禁止: 既定は4視点をインラインで順に実施。並列は明示指示時のみ
- 課題登録はしない: 指摘を洗い出して提示するまで。tracker 登録はユーザー承認後

## 4つの視点
1. アーキテクト: モジュール分担・ADR 整合・設計の一貫性・拡張性
2. 仕様レビュアー: URD↔SRS↔HLD↔LLD トレーサビリティ・曖昧さ・抜け漏れ・矛盾
3. データ/アルゴリズム: 境界条件・NODATA・サンプル代表性・性能/メモリ
4. 申請者/エンドユーザー: SOTA 申請 O/P 要件・エビデンス妥当性

## 手順
1. 対象文書（引数）を読む。関連する URD/SRS/HLD/LLD/ADR も必要に応じ参照
2. 各視点で指摘を抽出（根拠主義: 推測でなく文書の記述を引用して指摘）
3. 指摘を「視点 / 重要度（高・中・低）/ 内容 / 該当箇所 / 推奨対応」の表に集約
4. 視点横断の総評（最大の論点・トレードオフ）を 3〜5 行で
5. ユーザーに提示し、tracker 登録要否を確認（登録時は 1 論点 1 課題で issue/todo 振り分け）
