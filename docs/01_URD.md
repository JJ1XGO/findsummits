## 1. 目的・背景

SOTA（Summits On The Air）日本支部の対象サミットリストを最新化するため、
国土地理院の標高タイル（DEM5）を使って日本全国のサミット候補を解析し、
SOTA日本支部への更新申請に必要な成果物を生成する支援ツール。

## 2. 対象ユーザー・利用シーン

**対象ユーザー**: SOTA日本支部への申請者  
**利用シーン**: 定期的なSOTAサミットリスト更新申請の準備作業として使用する。

## 3. ユーザーニーズ

| ID | 要件 |
|---|---|
| UR-001 | 日本全国（176メッシュ）の山頂を網羅的に検出できること |
| UR-002 | プロミネンス≥150mのサミット候補を抽出できること |
| UR-003 | 現行SOTAリストと突合し、新規・変更（座標・標高）・削除の候補を識別できること |
| UR-004 | SOTA日本支部指定フォーマットの申請書XLSX（新規・変更・削除の3シート）を生成できること |
| UR-005 | 申請内容のエビデンスとなるCSV（サミット座標・標高・Keyコル座標・標高・プロミネンス）を生成できること |
| UR-006 | 国土地理院地図上での目視確認用GeoJSONを生成できること |
| UR-007 | 独立峰（大山・東北の孤立峰など）を含む全サミット候補を漏れなく検出できること |
| UR-008 | ドキュメントに従って環境構築から成果物生成まで実行できること |
| UR-009 | 仕様書・設計書の内容とプログラムの実装が整合していること |
| UR-010 | 国土地理院の利用規約およびアクセスマナーを遵守した方法でタイルを取得すること |

## 4. 前提・制約

- 標高データは国土地理院タイルのみ使用（DEM5a / DEM5b / DEM5c / DEM10b の優先順）
- プロミネンス判定基準はSOTAルール（≥150m）に従う
- 申請書フォーマットはSOTA日本支部が指定するXLSXテンプレートに従う
- 解析対象は日本国内の1次メッシュ全176メッシュ
- タイル取得時はインターネット接続が必要（解析・出力生成はオフラインで可）
- 地理院サーバへのアクセスはガイドラインに従い、User-Agent明示・リクエスト間隔を守る
- 本ツールは開発者本人の特定マシン上での動作を前提とする。詳細は [`environment.md`](environment.md) を参照

## 5. スコープ外（対象外）

- 日本以外のSOTA申請
- DEM1a（データ量がDEM5の25倍、精度向上が僅少なため採用しない）
- SOTA申請書の提出・承認プロセス（ツールは申請書生成まで。提出は手動）
- リアルタイム処理（バッチ処理のみ）
- 地形の現地確認（目視確認はGeoJSONを使って地図上で行う）
