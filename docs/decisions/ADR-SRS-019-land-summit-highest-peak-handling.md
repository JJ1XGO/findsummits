# ADR-SRS-019: 陸地最高峰の Key コル確定方式

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-12（2026-06-18 層2の実施箇所を [FR-022](../20_SRS.md#fr-022-コル充足判定) → [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) に改訂。ADR-SRS-027） |

> ※ **層2（陸地最高峰の手動確定を [FR-022](../20_SRS.md#fr-022-コル充足判定) が行う）** とした本 ADR Decision の箇所は、[ADR-SRS-027](ADR-SRS-027-fr022-purification-fr023-pipeline-control.md)（2026-06-18）によって supersede された。陸地最高峰の海面確定は **[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) が `merged_peak.csv` 生成時に毎回適用**する（案B）。

## Context

[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) で定義したコル検出ロジックは、山塊グループが解析範囲端（1px 海面ボーダー）に接触して flood が終了することを前提としている。しかし、本州最高峰の富士山・北海道最高峰の旭岳・九州最高峰の中岳（九重）は、6×6 ウィンドウ（解析半径約 185km）のどのコーナー配置でも陸地全体を囲むことができない。

その結果、これらのピークは 3×3 通常解析から N=6 広域解析まで全段階を経ても `key_col_resolved=false` のままとなり、[FR-022](../20_SRS.md#fr-022-コル充足判定) のエスカレーションが完了しても `key_col_resolved=false` が残存する。最終的に [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) が `is_key_col_unresolved` 不備フラグで異常終了するという仕様ギャップが本セッションで発見された。

一方、四国最高峰の石鎚山・九州内の他のピーク・小島の最高峰については、[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) の海面確定規則（山塊グループが解析範囲端に接触せず flood 完結）により 3×3 または広域解析内で自動確定できると想定される。

## Decision

**二層構造**で対応する。

### 層1: 海面確定規則（FR-006 自動確定・大多数の島嶼最高峰に適用）

[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) に海面確定規則を追加する。山塊グループが 1px 海面ボーダー（解析範囲を囲む人工的な海面帯）に一度も接触せず flood が完結した場合、そのピークを「解析窓内で陸地が孤立した最高点」と判断し、Key コル = 海面（0m）・`key_col_resolved=true`・プロミネンス = ピーク標高 とする。この場合も `col_lat`/`col_lon` は 0.0 に設定する（層2の陸地最高峰リストと同一 sentinel 表現に統一。これにより [FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合) の key_col Point 除外ロジックが「`col_lat`/`col_lon`=0.0 かどうか」で統一できる）。

この規則は四国の石鎚山・小島の最高峰・本土から切り離された半島のピーク等で広く機能する（3×3 解析で海面ボーダーに触れずに flood が完結する場合）。

### 層2: 陸地最高峰リスト（FR-022 による手動確定・大陸的な島嶼最高峰に適用）

富士山・旭岳・中岳（九重）の 3 件は本州・北海道・九州という大陸的な大きさの島嶼の最高峰であり、6×6 ウィンドウで囲い切れない。[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) が `merged_peak.csv` を生成するたびに、陸地最高峰リスト（内部データ）と近傍一致するピークを海面確定（Key コル = 0m・`key_col_resolved=true`）に更新する。これにより再統合のたびに確定が消えることもなく、[FR-022](../20_SRS.md#fr-022-コル充足判定)/[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) は陸地最高峰を特別扱いしない。（2026-06-18 改訂: [ADR-SRS-027](ADR-SRS-027-fr022-purification-fr023-pipeline-control.md)）

## Alternatives

| 案 | 却下理由 |
|---|---|
| 全陸地最高峰を手動リストで管理（海面確定規則なし） | 全国 3,000 件超の各島嶼最高峰を個別登録する必要がある。地理院タイル解析で自動確定できるものまでリストに依存するのは保守性が低い |
| N=6 残存ピークを自動的に海面確定 | どのウィンドウでも囲えないことを「完全確認」してから海面確定する。原理的には正確だが、真のコルが存在するケース（prefetch 漏れ・タイル欠損が原因で未確定のまま残ったピーク）まで誤って海面確定する危険がある。手動リストで対象を明示する方が安全 |
| [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) で `is_key_col_unresolved` 不備フラグを無視して続行 | SOTA 申請精度への影響が判断できないまま申請することになる。不可 |

## Consequences

1. **[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) 海面確定規則の副作用リスク**: タイル欠損（地理院未整備）やタイル全欠如（prefetch 漏れ）によって全ピクセルが NODATA になると、山塊グループが海面ボーダーに接触しないまま flood が完結し、「海面確定」が誤発動する。これを防ぐために [FR-014 異常系](../20_SRS.md#fr-014-広域結合解析オーケストレーション)（存在メッシュのタイル全欠如 → エラー中止）と整合させる
2. **石鎚山の検証**: 実装後、石鎚山（四国）が海面確定規則で 3×3 解析にて自動確定するかを実データで確認する。自動確定しない場合は陸地最高峰リストに追加する
3. **陸地最高峰リストのメンテナンス**: 当面の初期リストは 3 件（富士山・旭岳・中岳）。SOTA 申請対象外の陸地最高峰は含める必要がない（SOTA 登録されていなければ `merged_peak.csv` に出現しない）
4. **[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) での適用タイミング**: 陸地最高峰の海面確定は [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) が `merged_peak.csv` を生成するたびに実施する。フェーズ2 末尾（最初の統合時）に確定されるため、N=4 の広域解析には対象ピークとして含まれない（2026-06-18 改訂: [ADR-SRS-027](ADR-SRS-027-fr022-purification-fr023-pipeline-control.md)）
