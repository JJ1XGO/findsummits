# ADR-SRS-046: 解析済みウィンドウメッシュ集合による部分集合判定スキップ機構

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-30 |

## Context

[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)（広域結合解析オーケストレーション）は、コル未確定ピークに対して
N×N メッシュ（N=4/5/6）の 4 コーナー配置パターン（NW/NE/SW/SE）を順に試行する。
このとき、あるコーナーパターンが「すでに解析済みの範囲と完全に重複している」場合は
試行しても新たな情報が得られないためスキップすることが求められる。

しかし従来の SRS 記述「**それまでに解析済みのどの範囲と比べても 1 枚も増えない配置はスキップ**」は、
判定に用いるデータ構造とアルゴリズムが未定義だった。
実装者が判定方法を独自解釈すると、過積極スキップ（情報喪失）または過少スキップ（無駄な再解析）が発生するリスクがある。

同様に、[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)（3×3 解析）が生成したウィンドウ範囲も、
広域解析のスキップ判定に組み込む必要があるが、その経路も未定義だった。

## Decision

### 新内部データ: 解析済みウィンドウメッシュ集合（`<解析識別子>.meshset`）

[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)/[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) は各ウィンドウの解析完了後に、
そのウィンドウの「存在メッシュコード（日本全土１次メッシュコードリスト内のもの）のソート済みリスト」を
`<解析識別子>.meshset` ファイルとして書き出す。

- **生成元**:
  - [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション): 3×3 解析完了後（[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) 呼び出し後）に書き出す
  - [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション): 各コーナーパターン解析完了後（[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) 呼び出し後）に書き出す。
    早期終了でスキップされたコーナーパターンは書き出しを行わない（未試行のため）
- **消費元**: [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) が各コーナー試行前に全蓄積ファイルを読み込む
- **ファイル内容**: 存在メッシュコードのソート済みリスト（ピクセル位置対応は含まない）。
  物理ファイル形式・保存先パスは HLD で定義する
- **解析対象メッシュ範囲情報**（ピクセル位置対応を含む）は内部トランザクションのまま変更なし。
  新ファイルにはメッシュコード集合のみを含む

### スキップ判定: 単一ファイルとの部分集合判定

[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) は各コーナーパターンの試行前に、候補ウィンドウの存在メッシュコード集合を算出し、
蓄積済みの全 `.meshset` ファイルを走査する。

**スキップ条件**: 候補集合 ⊆ 蓄積済みの**いずれか 1 件**のメッシュコード集合

すなわち、単一の蓄積済み解析が候補ウィンドウの全存在メッシュをカバーしているならスキップする。

蓄積ファイルが存在しない場合（初回実行時）はスキップしない。

## Alternatives

**A. CSV ファイル名スキャンによるメッシュ集合再構成**

実行済みの per-mesh CSV ファイル名（`<N>-<meshcode>-<corner>.csv`）をスキャンして
コーナーごとのメッシュ集合を動的に再構成する案。

CSV ファイル名にはメッシュコード・コーナー情報が含まれるが、N×N グリッドの「存在メッシュ」
（日本全土１次メッシュコードリスト内のもの）は各コーナー配置時に算出した値であり、
CSV ファイル名からは再構成できない（日本全土１次メッシュコードリストと照合する追加処理が必要）。
実装コスト・誤りリスクが高いため却下。

**B. 全蓄積ファイルの和集合との比較**

全 `.meshset` ファイルのメッシュコードの**和集合** ⊇ 候補集合ならスキップする案。

例: 蓄積ファイル1 = {A, B}、蓄積ファイル2 = {B, C}、候補 = {A, B, C} の場合、
和集合 {A, B, C} ⊇ 候補集合 → スキップ判定される。
しかし候補ウィンドウは A・B・C が同一グリッド内に存在するため、
「A のコルが C 方向にある」など単一蓄積解析では得られない情報が生じうる。
過積極スキップにより解析精度が損なわれるため却下。

## Consequences

- [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) 出力テーブルに「解析済みウィンドウメッシュ集合」（内部データ）行が追加される
- [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) 入力テーブルに「解析済みウィンドウメッシュ集合（全蓄積ファイル）」（内部データ）行が追加される
- [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) 出力テーブルに「解析済みウィンドウメッシュ集合」（内部データ）行が追加される
- SRS §8.1 内部データ一覧に No. 13 として追加される
- [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) の「無効パターンのスキップ」説明が部分集合判定の具体的な記述に置き換わる
- 物理ファイル形式（拡張子・行フォーマット）は HLD が定義する
- N=5 で N=4 の配置と完全に重複するケースは、この判定で自然にスキップされる
