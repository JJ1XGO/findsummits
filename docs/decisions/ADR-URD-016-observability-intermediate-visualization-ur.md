# ADR-URD-016: 中間成果物の可視化検証要件（観測可能性）の UR 化

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-16 |

## Context

[FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合)（per-mesh ピーク候補 GeoJSON 統合）のレビューで、「[FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合) を最終段で1回だけ実行する」か
「[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) とセットで [FR-022](../20_SRS.md#fr-022-コル充足判定)
ループ内を毎回再入させる」かの設計判断が複数回揺れた（[ADR-SRS-024](ADR-SRS-024-fr018-loop-reentry-and-peak-filter.md)）。
原因は、揺れを決着させる根拠が URD に存在しなかったことにある。

ユーザーの本質的なニーズは次の通り: 解析パイプラインが各段階で生成する成果物（per-mesh
ピーク候補 GeoJSON・統合ピーク候補 GeoJSON 等の中間成果物を含む）を、
**生成されたタイミングで**地理院地図等に展開（手動ドラッグ＆ドロップで可）して可視化し、
ピーク・コル・各ゾーンの位置と対応関係の妥当性を目視確認したい。広域解析
（[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)）は計算負荷が高く待ち時間が長いため、
その間に途中経過を確認できることに実務上の価値がある。CSV（`merged_peak.csv` 等）は数値の集合
であり、地理的な形状・対応関係を直感的に把握できない。

既存 UR にはこのニーズに対応するものがない:

- **[UR-006](../10_URD.md#ur-006)**: 申請エビデンスとしての最終成果物（GeoJSON・HTML ビューア）の生成要求であり、
  申請目的が前提。開発・テスト中の中間確認は目的としていない。
- **[UR-012](../10_URD.md#ur-012)**（[ADR-URD-015](ADR-URD-015-terrain-image-validity-check-ur.md)）: 標高地形図 PNG による
  「解析データの読み込み正常性」の妥当性確認に限定され、GeoJSON によるピーク・コル・ゾーンの
  対応確認とは対象も精度も異なる。

このため、設計判断（ループ内再入の必要性）を裏付ける要件が URD レベルで欠落していた。

## Decision

[UR-013](../10_URD.md#ur-013) として以下の要件を URD に新設する:

> [UR-013](../10_URD.md#ur-013): 解析パイプラインが各段階で生成する成果物（per-mesh ピーク候補 GeoJSON・
> 統合ピーク候補 GeoJSON 等の中間成果物を含む）を、生成されたタイミングで地図上に可視化し、
> ピーク・コル・各ゾーン（アクティベーション／削除判定）の位置とそれらの対応関係の妥当性を
> 目視確認できること。CSV だけでは具体的な地理的形状・対応が把握できないため、GeoJSON 等の
> 可視化可能な形式での出力を要する。本要件は申請成果物の作成（[UR-006](../10_URD.md#ur-006)）ではなく、開発・テスト・
> 運用時に解析の妥当性を検証する観測可能性を目的とする。

**「観測可能性（[UR-013](../10_URD.md#ur-013)）」と他 UR との役割分担**:

| | [UR-012](../10_URD.md#ur-012)（妥当性確認画像） | [UR-013](../10_URD.md#ur-013)（中間可視化・観測可能性） | [UR-006](../10_URD.md#ur-006)（最終可視化・申請エビデンス） |
|---|---|---|---|
| 目的 | 標高データの読み込み正常性確認 | パイプライン中間成果物の妥当性検証（ピーク・コル・ゾーン対応） | 申請内容の最終的なエビデンス提示 |
| 対象成果物 | 標高地形図 PNG | per-mesh / 統合済み GeoJSON（中間） | `merged_summit.geojson`・HTML ビューア（最終） |
| 生成タイミング | 解析開始前（[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) 完了直後） | パイプライン各段階（per-mesh 出力時・統合時） | 解析完了後（フェーズ4） |
| 精度 | 長辺 6000px 縮小・気付きレベル | 地図上での精密な確認 | 地図上での精密な確認 |

なお、[UR-013](../10_URD.md#ur-013) が要求する「ピーク・コルの対応関係の可視化」は、現状の per-mesh / 統合 GeoJSON の
プロパティ設計（[ADR-SRS-022](ADR-SRS-022-per-mesh-geojson-property-design.md) の join 方式。
GeoJSON はピーク座標・ゾーン形状のみを持ち、コル座標は `merged_peak.csv` 側にのみ存在する）では
直接満たせない。実現方式（GeoJSON へのコル情報付与、または別途の対応表示手段）は本 ADR の
スコープ外とし、SRS 以降の設計検討に委ねる。

## Alternatives

**1. [UR-006](../10_URD.md#ur-006) を拡張する（却下）**:
[UR-006](../10_URD.md#ur-006) は申請エビデンスとしての最終成果物が前提であり、開発・テスト中の中間確認とは目的が
異なる。同一要件に混在させると「最終／中間」の区別が失われ、SRS 側で生成タイミングの要求を
読み取れなくなる。

**2. [UR-012](../10_URD.md#ur-012) を拡張する（却下）**:
[UR-012](../10_URD.md#ur-012) は標高地形図 PNG という形式・精度（気付きレベル）に限定された要件であり、GeoJSON による
ピーク・コル・ゾーンの精密な対応確認とは対象も保証範囲も異なる。拡張すると [UR-012](../10_URD.md#ur-012) の限定的な
保証範囲（NODATA 識別不可等）まで誤って引き継がれる。

**3. 要件化しない（却下）**:
[FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合) のような設計判断のたびに根拠が定まらず揺れ続ける。CLAUDE.md の仕様優先原則に反し、
コード側の都合（実装の簡便さ）で仕様が決まってしまうリスクがある。

## Consequences

- [UR-013](../10_URD.md#ur-013) は中間成果物の**生成タイミングでの可視化**を要求するため、[FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合)
  を [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) とセットでループ内再入させる設計（[ADR-SRS-024](ADR-SRS-024-fr018-loop-reentry-and-peak-filter.md)）の
  根拠が URD レベルで確立する。
- [UR-013](../10_URD.md#ur-013) の「ピーク↔コル対応の可視化」は現行 GeoJSON 設計では未対応。SRS 以降で実現方式
  （GeoJSON へのコル情報付与・[ADR-SRS-022](ADR-SRS-022-per-mesh-geojson-property-design.md) の見直し等）
  を別途検討する必要がある（別 ISSUE で管理）。
- 今後、中間成果物に関する設計判断（生成タイミング・再生成方式等）は [UR-013](../10_URD.md#ur-013) を根拠として
  判断できる。
