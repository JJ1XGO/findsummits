# ADR-008: dominant peak 特定アルゴリズム

| 状態 | 採用・未実装 |
| 決定日 | 2026-05-14 |

## Context

削除候補となった SOTA サミット（`match_status="deleted"` の sota_summit feature）に対して、その dominant peak（どの検出ピークが当該サミットの存在を「支配」しているか）を特定する必要がある。

dominant peak の特定には次のエッジケースへの対処が必要:

1. **複数包含**: 複数の検出ピークのコル等高線ポリゴンに SOTA サミット座標が含まれる（縦走路上など）
2. **包含なし**: いずれの検出ピークのコル等高線ポリゴンにも含まれない（メッシュ境界での truncation・SOTA リストの座標精度等）

## Decision

3段階の判定を行う:

1. **コル等高線ポリゴン包含判定**: SOTA サミット座標が含まれる `feature_type="key_col_boundary"` ポリゴンを持つ検出ピークを候補とする（point-in-polygon 判定）
2. **複数包含時のタイブレーク**: 候補が複数の場合は、SOTA サミット座標と各候補ピーク座標の距離が最も近いものを dominant peak とする（Haversine 公式）
3. **フォールバック（包含なし）**: いずれのポリゴンにも含まれない場合は、全検出ピーク中で最も近いものを dominant peak とする（Haversine 公式）

dominant peak が確定したら以下のカラムを削除候補サミットの行に付与する:

- `dominant_peak_code`: dominant peak のサミットコード（仮サミットコードの場合もある）
- `dominant_peak_dist_m`: dominant peak 座標から SOTA サミット座標までの距離 m（Haversine 公式）

## Alternatives

**単純最近接のみ（コル等高線判定を使わない）**  
実装は最もシンプルだが、縦走路上に複数のサミットが並ぶ場合にプロミネンス計算結果との整合が取れない。コル等高線はプロミネンスを規定するKeyコルに基づいて生成されるため、包含判定との整合性が高い。

**複数包含時のタイブレークを「最高コル」で決定**  
コル等高線の标高が高いほど「支配力が強い」とも言える。ただし実装が複雑になり、かつ最近接で十分な精度が得られると判断した。

**フォールバックなし（包含なしはエラー）**  
データの問題（メッシュ境界 truncation・SOTA リスト座標精度）で包含なしが発生しうるため、エラーにすると実用的でない。フォールバックで処理を継続し、`dominant_peak_dist_m` が大きい行は人手確認のシグナルとして使う。

## Consequences

- 縦走路上のサミットや古い座標データでも安定して dominant peak が特定できる
- `dominant_peak_dist_m` が大きい行はフォールバックが使われた可能性を示す（申請時の人手確認対象）
- フォールバック使用時はログに警告を出力する
