# ADR-SRS-031: 仮サミットコード連番上限の設定可能化・00 始まり化

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-18 |

## Context

[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の仮サミットコード採番では、連番上限を `A99`（1 エリアあたり 99 件）で固定し、超過時は異常終了して人手判断を仰ぐ設計とした。これは「100 件超は解析範囲やプロミネンス閾値の異常を示唆する」という検知目的に基づく。

しかし初年度の全国解析では、解析パラメータが適正であっても、一部エリアで新規ピーク候補が 100 件を超える可能性がある。初年度は実際の採番結果を確認してから判断したいため、上限を柔軟に設定できるようにする必要がある。次年度以降は通常 `A99` の範囲内で収まると想定されるため、デフォルト値は保守的に維持する。

## Decision

### 1. 連番上限を設定可能項目化

[2.2.1 設定可能項目](../20_SRS.md#221-設定可能項目) に以下を追加する:

| 項目名 | 意味 | デフォルト値 | 許容範囲 |
|---|---|---|---|
| 仮サミットコード連番上限 | 同一エリアに採番する仮コードの最大 prefix 文字。この文字の `99` を超えたら異常終了 | A | A〜Z |

- **デフォルト `A`**: `A00`〜`A99`（100 件まで）で異常検知を維持する。通常運用・次年度以降はこの値を使用する。
- **初年度のみ `Z` 等に設定**: `A00`〜`Z99`（最大 2,574 件）まで許容し、全件採番して実数を確認する。確認後、次年度に `A` へ戻すことで異常検知が復活する。

超過時の動作は変わらず「エラーメッセージ（地域コード・超過件数）を出力して異常終了」。

### 2. 連番を 00 始まりに変更

連番を `01` 始まり → **`00` 始まり** に変更する。

- 採番は `A00`〜`A99`（1 prefix あたり **100 件**）。
- 旧表記例 `JAx/XX-A01` → 新表記例 **`JAx/XX-A00`**（01 は例示であり先頭は 00 から始まる）。
- `ZZ/ZZ-A01`（海上・地域不明フォールバック）→ **`ZZ/ZZ-A00`** に統一。

## Alternatives

### 案 A: `A99` 固定を維持（不採用）

現状の固定上限を維持する案。初年度に 100 件超が発生すると実行が異常終了し、全件を確認できない。初年度の実態把握を妨げるため不採用。

### 案 B: 無制限自動拡張（不採用）

`A99` 超過時に自動で `B00` へ進む案。設定変更が不要だが、異常検知の機能が完全に失われる。「解析異常の早期検知」という元の設計意図が消えるため不採用。

### 案 C: 連番を 01 始まりのまま設定可能化（不採用）

00 始まり化をせず上限だけ設定可能にする案。しかし 01 始まりでは 1 prefix あたり 99 件と半端になり、設定値（例: `A`）から上限件数（99 件 vs 100 件）が直感的に計算しにくい。00 始まりにすることで 1 prefix = 100 件という計算が自然になる。→ 不採用。

## Consequences

### SRS への影響

- **2.2.1 設定可能項目**: `仮サミットコード連番上限` の行を追加。
- **FR-009 採番規定**: フォーマット例・採番開始番号・連番上限の記述を以下のように更新:
  - フォーマット例: `A01` → `A00`
  - 採番文言: `01 からリセット` → `00 からリセット`
  - 上限記述: 固定 `A99` → 設定可能項目（「仮サミットコード連番上限」）への参照に書き換え
- **関連箇所（フォールバック・例示）**: `ZZ/ZZ-A01` → `ZZ/ZZ-A00`、`JAx/XX-A01` 表記例 → `JAx/XX-A00` へ全更新。
