# ADR-URD-017: HTML ビューアのマーカー描画方式（クライアント側描画の採用）

| 状態 | 採用・実装済み |
| 決定日 | 2026-06-25 |

---

## Context

HTML ビューアのモックアップ開発時（`docs/mockup/viewer_mockup.html`）、地理院サーバ上の
アイコン画像（PNG）をマーカーとして表示する方式を試験した。サミット候補・既存サミット等の
マーカーが多数重なる状態でパン・ズーム操作を行ったところ、アイコン取得のネットワーク遅延と
DOM 要素の再描画コストが重なり、フレームレートが大幅に低下して実用に耐えないとユーザーが判断した。

この描画性能の問題を要求・設計決定として記録する。関連 UR: [UR-014](../10_URD.md#ur-014)。

描画応答性の定量基準として **RAIL パフォーマンスモデル**（Google、web.dev）を採用する。

| 観点 | 指標 | 値 |
|---|---|---|
| 連続操作（パン・ズーム）の滑らかさ | RAIL "Animation" | 60fps（フレーム ≤16ms） |
| 入力→可視応答 | RAIL "Response" | 入力処理 ≤50ms、可視応答 ≤100ms |
| 現行 Core Web Vitals（参考） | INP "good" 閾値 | ≤200ms（2024-03 より FID を置換） |

出典: [Measure performance with the RAIL model - web.dev](https://web.dev/articles/rail)

## Decision

マーカーは**クライアント側（ブラウザ内）で描画**し、外部サーバ（地理院等）のアイコン画像取得に
依存しない方式を採用する。

モックアップでの実装形態（`preferCanvas: true`・`L.canvas()`・`L.CircleMarker` ベースの
カスタム三角形マーカー）を基本方針として引き継ぐ。描画機構（Canvas の具体的なレイヤー構成・
ズーム別サイズ等）の詳細は HLD に委ねる（[ADR-SRS-034](ADR-SRS-034-viewer-reference-layers.md)
の「描画機構は HLD、SRS は観測可能な挙動のみ」方針を踏襲）。

## Alternatives

1. **地理院サーバアイコン継続**（却下）: PNG 取得のネットワーク遅延 + DOM `L.icon` の
   再描画コストでパン・ズーム時に 60fps を維持できず、実用不可とユーザーが判断した。

2. **SVG/DOM マーカー（`L.divIcon`）**（部分採用・補助的用途のみ）: DOM 要素を生成するため
   マーカー多数時の再描画コストが高く、主マーカー（summit/peak/key_col）には不適。
   モックアップでは既存サミット（`_ref=true`）には Canvas 円を使いつつ、一部の要素に
   `L.marker` を補助的に使用している。

3. **Canvas クライアント描画**（採用）: ブラウザ内 Canvas で全マーカーをラスター描画。
   ネットワーク依存なし・DOM 要素生成なし。`L.CircleMarker`（`preferCanvas: true`）は
   当たり判定・ポップアップ・ズーム連動を親クラスから流用できるため実装コストも低い。

## Consequences

- **[UR-014](../10_URD.md#ur-014)**（新規）をユーザーニーズに追加: パン・ズームの実用的な滑らかさを要求として明記
- **[NFR-010](../20_SRS.md#nfr-010-描画応答性連続操作の滑らかさ)**（新規）を SRS に追加: RAIL 標準値（60fps/16ms・応答≤100ms）を非機能要件として規定
- **SRS [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様)** に観測可能な実行方式を1行追加:
  「マーカーはクライアント側で描画し、外部サーバのアイコン画像取得に依存しない」（[FR-013](../20_SRS.md#fr-013-html-ビューア生成) は生成機構のみを扱うため、ビューアの機能・挙動を定義する [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) に配置）
- 実装機構（Canvas レイヤー構成・サイズ段階等）は引き続き HLD に委譲
- 地理院サーバへの画像リクエストが削減されるため、アクセスマナー（[NFR-004](../20_SRS.md#nfr-004-アクセスマナー)）にも副次的に貢献
