# ADR-SRS-018: 北方領土除外のタイル取得段階での実施

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-07 |

## Context

北方領土（択捉・国後・色丹の北方領土 6 村、行政区域コード N03_007: 01695〜01700）に所在するピークは SOTA 日本支部の管轄外であり、解析対象から除外する方針は [ADR-URD-005](ADR-URD-005-northern-territories-exclusion.md) で確定済み。

除外をどの段階で行うかについて、2 つの方式が候補となった。

## Decision

**FR-001（タイル取得段階）でスキップする**方式を採用する。

FR-017 が生成する北方領土除外タイルリストを FR-001 が読み込み、リスト内のタイル（ズームレベル 15 の x/y 整数ペア）に対して HTTP リクエストを発行しない。

### DEM10b（ズームレベル 14）の扱い

DEM5a/5b/5c はズームレベル 15、DEM10b はズームレベル 14 で配信される。
北方領土除外タイルリストは Z15 形式のみだが、DEM10b（Z14）についても除外が必要である。

実データ確認（2026-06-28）により、国後島の Z14 タイル（`dem_png/14/14839/5935`）が HTTP 200 を返すことを確認した（択捉島・色丹島は HTTP 404）。地理院は北方領土の DEM10b タイルを一部提供しているため、除外処理を省略すると国後島等のピーク候補（爺爺岳 1,822m 等）が解析対象に流れ込む。

**対応方針**: FR-001 が DEM10b（Z14）タイルを取得する際、Z15 除外リストの各エントリ `(x, y)` を `(x // 2, y // 2)` で変換した Z14 タイルをスキップする。変換後の重複エントリはユニーク化する。

この変換で本土タイルが誤除外されるリスクは実質ゼロである（ADR-URD-005 で北方領土と北海道の最近接 Z15 タイル間距離が約 17.9 km（Z15 タイル辺長 ~1.2 km の約 15 タイル分）と確認済みのため、Z14 スケール（辺長 ~2.4 km）でも誤除外は生じない）。

## Alternatives

**(a) FR-004（タイル読み込み時 NODATA マスク）— 旧方式・却下**

- FR-004（C エンジン）が北方領土除外タイルリストを読み込み、タイル読み込み時に該当タイルの全ピクセルを NODATA (R=128, G=0, B=0) として扱う
- FR-001 は北方領土タイルも含めて全タイルを取得するため、通信・容量が無駄になる
- C エンジンにファイルパース処理（除外リスト読み込み）が追加され、責務が拡大する
- 北方領土除外という業務ルールが FR-004（地形解析エンジン）に埋め込まれてしまい、意味的なコンポーネント境界が崩れる

**(b) FR-001（タイル取得段階）でスキップ — 採用**

- FR-017 が FR-001 の必須前提となることで、依存順（前処理→取得）と章立てが一致する
- 北方領土タイルの HTTP リクエストが発生しないため、通信量・取得時間・ローカルキャッシュ容量を削減できる
- C エンジン（FR-004）は「ローカルキャッシュにあるタイルが全て解析対象」という素直な構造に戻る
- 北方領土除外という業務ルールが SRS 上の入口（タイル取得段階）で完結する

## Consequences

- **正の影響**: 通信量・取得時間・ローカルキャッシュ容量の削減。FR-004 責務の縮小。コンポーネント責務の明確化。
- **負の影響**: FR-017（N03 ZIP 配置・前処理実行）が FR-001 の必須前提となるため、N03 ZIP が未配置の場合は FR-001 を実行できない。
- **フォールバック**: 北方領土除外タイルリスト未存在時は FR-001 がエラー終了する（旧方式では FR-004 が除外スキップで解析を続行していたが、本方式では前提条件として扱う）。
- **実装**: `prefetch_tiles.py`・`preprocess_pref_boundaries.py` で対応予定（HLD/LLD ステージで詳細化）
