## Context

SOTA プロミネンス 150m 判定には「Key コル（最低鞍部）」の標高が必要。  
Key コルは対象サミットから数十 km 離れた場所にある場合があり、  
解析範囲が狭いと Key コルが範囲外に出て誤検出（プロミネンス = ピーク標高）になる。

初期実装では 8 タイルパディング（≒9.6km）を使っていたが、  
これはユーザー合意の「3×3 フルメッシュ」から無断で変更したものであり、  
精度不足・仕様違反として記録されている（合意なしの仕様変更は禁止ルールに抵触）。

## Decision

- 対象メッシュを中心に最大 **3×3 の 1 次メッシュ**（最大 9 メッシュ）を結合して解析
- **出力は解析対象メッシュ全体の地理的範囲内のピーク**（中心メッシュ内に限定しない）。同一ピークは複数の 3×3 解析の per-mesh CSV に重複出力され、統合段階の重複排除と `analysis_count` / `expected_count` による安定性評価に利用する（SRS [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) / [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) 参照）
- 解析範囲: 中心から各方向 74km（緯度方向）〜 88km（経度方向@35°N）

日本の SOTA 対象峰の Key コルは 3×3 フルメッシュ範囲内に収まることを確認済み。

## Alternatives

| 案 | 却下理由 |
|---|---|
| 8 タイルパディング（≒9.6km） | Key コルが範囲外になるケースがある。精度不足。 |
| オフセットグリッド方式 | メモリ効率は良いが実装複雑度が高い。3×3 方式で精度要件を満たすため不採用。 |
| RDB（台帳）方式 | 実装が複雑。Union-Find をまたぐ Key コル解決ロジックが非自明。 |
| 階層的 Union-Find 分割（タイルごとのローカル UF ＋境界マージ。2026-07-11 検討・v1.0 見送り） | v1.0 では不採用。現行要件（[NFR-002](../20_SRS.md#nfr-002-メモリ使用量) メモリは実測充足済み、[NFR-005](../20_SRS.md#nfr-005-処理時間目標) 処理時間目標を超える実害は確認されていない）は 3×3 方式で満たしており、3×3 前提は SRS の複数 FR（[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)/[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算)/[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合)/[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定)/[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)/[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成)/[FR-023](../20_SRS.md#fr-023-解析パイプライン制御)）と ADR-SRS-004 の広域エスカレーション設計に織り込み済みで、SRS 確定間近の時点で波及に見合う駆動要件がない。また先行実装（Parallel Priority-Flood, Barnes 2016）が解くのは連結性の問題であり、本プロジェクト固有の「成分マージ時の Key コル特定」がタイル境界マージで正しく保存されるかは未立証。**ただし却下ではなく v2.0 の本命候補**（実現可能性検証を経て採否を判断する）: [URD 将来スコープ](../10_URD.md#7-将来スコープv20-候補)（解析効率化・DEM1a 追従）の実現にはモノリシック方式（DEM5 で実測 57GB・DEM1a はデータ量 25 倍）が成立しない見込みのため、本方式への転換が必要になる。実現可能性検証は独立課題として起票済み（2026-07-11）。詳細: [`research/rust-cpp-and-scalable-analysis-research.md`](research/rust-cpp-and-scalable-analysis-research.md) §E |

## Consequences

- 解析メモリ: 最大 56.9GB（中心付近メッシュ・62GB マシンでスワップを使いながら完走を確認）
- 各タイルが最大 9 回解析される（隣接 9 メッシュがそれぞれ中心に置く際に重複）
- メモリ制約が厳しいため、中心付近のメッシュでは並列数を絞る運用が必要
