# ADR-SRS-040: ベースライン文書からの内部トラッカーID排除方針

| 状態 | 採用・実装済み |
| 決定日 | 2026-06-27 |

## Context

`mgmt/tracker/`（ISSUE 実体 `issues.json`）は devel ブランチでのみ git 管理され、
リリース時に `git rm -r mgmt/` で main から除外される（`docs/CLAUDE.md` ブランチ運用ルール参照）。

一方、main にも持っていくベースライン文書（URD/SRS/ADR/research）には
`ISSUE-094` のような**内部トラッカー ID がテキストとして散在**していた。
これらの ID は主に「いつ・どの議論で決まったか」を示す経緯タグとして書かれている。

第三者が main を見たとき、トラッカー実体（`mgmt/tracker/`）は存在しないため、
ISSUE-ID は辿る先がなく意味を成さない。また一部は「〇〇は ISSUE-XXX で管理」という
生き依存の形をとっており、特に意味が失われる。

課題運用ルール（[CLAUDE.md](../../CLAUDE.md)「課題管理ルール」）では
「issue のスコープ＝決着の ADR/SRS 記録まで」と定めており、
決定内容そのものは ADR/SRS 本文に self-contained で記録済みであることが保証される。
したがって ID を除去しても情報は失われない。

既存の問題として、`docs/decisions/ADR-SRS-018-...:39` に
`[ISSUE-056](../../mgmt/tracker/)` 等の Markdown リンク形式の参照が2件あり、
`docs/CLAUDE.md`「mgmt/ へのパス参照禁止」に違反していた。
さらに `scripts/lint_docs.py` の broken-link 検査は `.md` 終端リンクのみ対象のため
末尾 `/` の mgmt パスリンクを見逃していた。

## Decision

1. **main に出るベースライン文書（`docs/` 全体）から ISSUE-ID をすべて排除する**。
   経緯の文脈（日付・議論の要旨）は本文に残す。ID だけを削除する。
   - 経緯タグ例: `FR-006 レビュー（2026-06-14）で指摘された` のように日付・文脈を残す
   - 生き依存例: 「〇〇は後続ステージで対応」のように一般化して ID への依存を切る
   - ファイル名に ISSUE-ID を含む research ファイルは `git mv` でリネームし参照を更新する

2. **`mgmt/tracker` の git 管理は維持する**。docs から ID を消せば main には出ない。
   devel ブランチでの変更履歴・バックアップを保つ意義がある。

3. **`scripts/lint_docs.py` に検査C を追加し再発防止を機械化する**。
   本文中の `ISSUE-\d+` パターンと `](../mgmt/` 等の mgmt パス参照を検出して違反報告する。

4. **`docs/CLAUDE.md` の参照ルールに明文化する**。
   「docs 配下に内部トラッカー ID（`ISSUE-XXX`/`BUG-XXX`）を書かない。経緯は日付・文脈で残す」
   を既存の `mgmt/ パス参照禁止` と並べて記載する。

## Alternatives

### A. リリース時に機械除去する（スクリプトで一括削除）

- devel では ISSUE-ID を書き続け、`release/*` 作成時のスクリプトで一括削除する
- 却下理由: リリース作業が複雑化し漏れのリスクがある。また devel で読む設計者にも
  「この ID は辿れるのか」と混乱を与える。早期排除のほうがシンプル。

### B. ISSUE-ID を残す（何もしない）

- 第三者向けではなく開発者向けの経緯情報として容認する
- 却下理由: main は公開ブランチであり、辿れない ID はノイズにしかならない。
  ユーザーが「今のうちに排除したい」と明示したため。

### C. 正式仕様に関係のない経緯タグのみ排除し、生き依存は残す

- 「管理は ISSUE-XXX で」という記述だけ残す
- 却下理由: main でトラッカーが存在しない以上、残存する生き依存も意味をなさない。
  全件排除が一貫している。

## Consequences

- **改善**: main を見た第三者が辿れない内部 ID によって混乱しなくなる。
- **改善**: lint 検査C により今後の docs 編集で ISSUE-ID の混入が機械的に検出される。
- **制約**: 今後 docs に「〇〇は ISSUE-XXX 参照」と書くことは禁止。経緯は日付や
  ADR へのリンクで記録する。
- **制約**: BUG-XXX も同様の理由で docs から除外する（`BUG-XXX` も検査C の対象）。
