# ADR-SRS-023: FR-008 統合対象メッシュコードリストの入力分離

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-16 |

## Context

FR-008（per-mesh CSV 統合）レビューで、入力「1次メッシュコードリスト」の役割が曖昧であることが
発見された。入力表のデフォルト欄は「未指定時は利用可能な全 per-mesh CSV を読み込む」と
*入力フィルタ*として記述する一方、説明欄では同じリストを `expected_count`（期待解析回数）算出の
基準としてのみ使用していた。1つの入力に2つの異なる役割（フィルタ／統計基準）が重なっており、
以下の問題があった。

**問題1: フィルタと統計基準の混在によるロジック破綻**

リストを「フィルタ」と「`expected_count` 基準」の両方に流用すると、結合テスト等で範囲を絞った
ときに `expected_count` も絞った範囲基準で算出されてしまう。これは「対象範囲を絞っても、その
範囲の各メッシュが本来想定される周辺メッシュで解析されているか」を検証できなくする。
範囲端メッシュは本来周辺メッシュ不足で `unstable` になるべきだが、絞った範囲を正として
`expected_count` を再計算すると `analysis_count == expected_count` となり誤って `confirmed` に
なってしまう。

**問題2: リスト省略時の `expected_count` が空欄になる未定義動作**

入力表は「リスト省略時は全 per-mesh CSV を読み込む」としながら、説明欄は「リストが省略された
場合も `expected_count` は空欄」としていた。`stability` 判定（`analysis_count ≠ expected_count`
で `unstable`）が `expected_count` 空欄時にどう評価されるか未定義だった。

**問題3: 広域 per-mesh CSV のフィルタ対象が未定義**

「対象を絞る」場合に、広域モード（`analysis_id` 接頭辞 `4/5/6`）の per-mesh CSV をフィルタ対象に
含めるかどうかが規定されていなかった。

## Decision

入力を **2 つのリストに分離**する。

| 入力 | 役割 | デフォルト |
|---|---|---|
| `対象1次メッシュコードリスト`（ユーザー入力・任意） | **入力フィルタ**。統合対象の per-mesh CSV を絞り込む | 日本全土1次メッシュコードリスト（全土） |
| `日本全土1次メッシュコードリスト`（内部データ・必須・既存ベースラインデータを FR-008 の入力として追加） | **`expected_count` 算出基準**。3×3 隣接カウントの母集合 | — |

**統合対象ルール**:
- `対象1次メッシュコードリスト` 指定時: 指定メッシュコードの**通常 per-mesh CSV のみ**を統合対象とする。**広域 per-mesh CSV は対象外**とする（結合テスト等で範囲を絞る用途を想定し、広域解析の複雑な依存関係を持ち込まない）
- 未指定時（デフォルト=全土）: ディレクトリ内の**通常+広域すべて**を統合対象とする（フルパイプライン実行時の挙動）
- [FR-022](../20_SRS.md#fr-022-コル充足判定) のエスカレーションループ内から FR-008 を再実行する場合は、常に `対象1次メッシュコードリスト` を渡さない（全土デフォルトで通常+広域を統合する）。ループはエスカレーション段階で生成された広域 per-mesh CSV を取り込む必要があるため、限定フィルタと両立しない

**`expected_count` の算出基準**:
- `対象1次メッシュコードリスト` で範囲を絞っても、`expected_count` は常に **日本全土1次メッシュコードリスト基準**で算出する（範囲を絞った結果に影響されない）
- これにより、範囲端メッシュは周辺メッシュ不足で `analysis_count < expected_count` となり、`stability=unstable` と正しく判定される。「対象範囲を絞っても、その範囲が本来想定される周辺メッシュで解析されていなければ不安定とみなす」という意図を構造的に表現する
- 日本全土1次メッシュコードリストは常に入力として存在するため、`expected_count` が空欄になるケース（問題2）は発生しない

**代表採用ロジックの完全定義**（複数解析の重複レコードから 1 件を選ぶ優先順位）:

1. `key_col_resolved=true` を `false` より優先する
2. `true` 同士は `col_elev`（コル標高）降順で最も高いものを優先する（保守的評価）
3. `col_elev` が同値の場合は、通常モード（L15・接頭辞 `3`）を広域モード（L14・接頭辞 `4/5/6`）より優先し、さらに同値であれば `analysis_id` 昇順で一意に決定する（[NFR-003](../20_SRS.md#nfr-003-再現性決定論的出力) 担保）
4. 全レコードが `key_col_resolved=false` の場合は `false` のまま維持する（[FR-022](../20_SRS.md#fr-022-コル充足判定) がエスカレーション対象として抽出する）

## Alternatives

**A: 単一リストのままデフォルトを日本全土に変更するだけ**

入力リストを1つのまま、デフォルト値だけ「日本全土」に変更する案。問題1（フィルタと統計基準の
混在）が解決しないため却下。範囲を絞った瞬間に `expected_count` の基準も連動して縮小し、
範囲端の不安定性を検出できなくなる。

**B: `対象1次メッシュコードリスト` を `expected_count` 基準にも流用**

絞り込みリストをそのまま `expected_count` 算出にも使う案。実装は単純だが、限定範囲の結合テスト
結果が「周辺メッシュ未解析」を検出できず誤って `confirmed` と判定される。テストの信頼性を
損なうため却下。

**C: `対象1次メッシュコードリスト` 指定時も広域 per-mesh を統合対象に含める**

フィルタ指定時に通常+広域の両方を対象とする案。広域 per-mesh CSV は [FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)（エスカレーションループ）が生成するため、限定範囲テストに広域解析の前提（コル未確定ピークの広域結合解析）を持ち込むことになり、テストのスコープが肥大化する。却下し、フィルタ指定時は通常のみとした。

## Consequences

- **FR-008**: 入力を `per-mesh ピーク候補 CSV` / `対象1次メッシュコードリスト` / `日本全土1次メッシュコードリスト` の3行に再編。出力 `merged_peak.csv` の保存先パスを明記（`$DATA_DIR/results/merged_peak.csv`）。説明部に統合対象ルール・代表採用ロジック4段・`expected_count` 全土基準化を明記
- **FR-022**: ループ内 FR-008 再実行時は `対象1次メッシュコードリスト` を渡さない旨を明記
- **データ辞書 7.2**: `日本全土1次メッシュコードリスト` の参照 FR に FR-008 を追加
- **テスト性への影響**: `対象1次メッシュコードリスト` 指定時のコンポーネントテストは「通常 per-mesh 統合のみ」を検証する。エスカレーションループ（広域統合）の検証は、fixture（合成 unresolved ピーク + 合成広域 CSV）または DATA_DIR をテスト地域に限定したデフォルトモード実行で別途担保する
- **コード追従（別タスク）**: `scripts/merge.py` の `--mesh-list` 指定時の絞り込み実装（通常 per-mesh のみ・広域除外・`expected_count` 全土基準）を本 ADR に合わせて修正する
