# ADR-SRS-008: dominant peak 特定アルゴリズム

| 状態 | 採用・未実装 |
| 決定日 | 2026-05-14 |
| 最終更新日 | 2026-05-21 |

## Context

削除候補となった SOTA サミット（`match_status="delete"` の summit feature）に対して、その dominant peak（どの検出ピークが当該サミットの存在を「支配」しているか）を特定する必要がある。

dominant peak の特定には次のエッジケースへの対処が必要:

1. **複数包含**: 複数の検出ピークの delete判定ゾーンに SOTA サミット座標が含まれる（縦走路上など）
2. **包含なし**: いずれの検出ピークの delete判定ゾーンにも含まれない（[ADR-SRS-011](ADR-SRS-011-delete-zone-polygon.md) で `summit.match_status="unmatched"` として merge.py を非ゼロ終了させる仕様。本 ADR の判定対象には含まれない）

（注: 2026-05-21 [ADR-SRS-011](ADR-SRS-011-delete-zone-polygon.md) 適用により、判定の根拠ポリゴンは「コル等高線ポリゴン」から「delete判定ゾーンポリゴン」（`feature_type="delete_zone"`）に変更された。判定アルゴリズム本体（最小プロミネンスのタイブレーク）は維持。）

## Decision

2段階の判定を行う:

1. **delete判定ゾーン包含判定**: SOTA サミット座標が含まれる `feature_type="delete_zone"` ポリゴンを持つ検出ピークを候補とする（point-in-polygon 判定）
2. **複数包含時のタイブレーク**: 候補が複数の場合は、**プロミネンスが最小のピーク**を dominant peak とする。プロミネンスが最小のピークは「親ピークへ最も早く合流する局所的な隆起」であり、地形学的に delete 候補サミットと同一の山塊に属していると見なせる

フォールバック（包含なし）は廃止する。いずれの delete判定ゾーンにも含まれない場合は**ログ警告を出力して処理を中止**し、人手判断に委ねる（`summit.match_status="unmatched"`、[ADR-SRS-011](ADR-SRS-011-delete-zone-polygon.md)）。

dominant peak が確定したら以下のカラムを delete サミットの行に付与する:

- `dominant_peak_code`: dominant peak のサミットコード（仮サミットコードの場合もある）
- `dominant_peak_dist_m`: dominant peak 座標から SOTA サミット座標までの距離 m（Haversine 公式。人手確認用として出力）

**データ構造の補足**: `merged.csv` には検出ピーク行と既存 SOTA サミット行が混在する。処理方向は「delete サミットを外側ループ」とし、各 delete サミット座標に対して全 delete判定ゾーンを照合する。

**空間インデックス**: delete判定ゾーンの包含判定は `shapely.strtree.STRtree` を用いて高速化する（アクティベーションゾーンの matched 判定も同じ STRtree を共用する）。

**複数 delete サミットから同一ピークへの参照**: 縦走路上に複数の delete 候補サミットがある場合、それぞれが独立して処理され、同一ピークが複数の delete サミットの dominant peak となることがある。論理矛盾はない（各サミットの dominant_peak_code が同一ピークを指すだけ）。

## Alternatives

**複数包含時のタイブレークを「Haversine 最近接」で決定**（2026-05-14 初版）  
距離が近いほど関連性が高いという直感的な方針。ただし、地形的根拠がない。複数のコル等高線ポリゴン内にサミット座標が含まれるということは、複数ピークが同一山塊を「包含している」状態であり、「どのピークが最もそのサミットと同一の局所的な隆起か」を表現するには最小プロミネンスのほうが適切。→ 最小プロミネンスに変更（2026-05-19）

**単純最近接のみ（ゾーン包含判定を使わない）**  
実装は最もシンプルだが、縦走路上に複数のサミットが並ぶ場合にプロミネンス計算結果との整合が取れない。delete判定ゾーンは Key コルとプロミネンス連動 + 上限キャップに基づいて生成されるため、包含判定との整合性が高い。→ 不採用

**フォールバック（包含なし時に全ピーク中の最近接を採用）**（2026-05-14 初版）  
データ問題による包含なしを想定してフォールバックを設けた。しかし FR-014 のフェーズ3.5 広域再解析（N=4→5→6 エスカレーション）完了後に `key_col_resolved=false` が残るのは陸地最高峰（島嶼部最高峰含む）に限られ、発生頻度が極めて稀。稀少ケースを機械的に処理するより、ログ警告 + 処理中止で人手判断に委ねるほうが安全。→ フォールバック廃止（2026-05-19）

**陸地ポリゴンによる陸地最高峰フォールバック**  
N03 行政区域データを拡張して陸地ポリゴンを整備し、陸地最高峰を機械的に特定する案。対象は年間 0〜2 件程度と推定されるため YAGNI（前処理拡張コストが利用機会に見合わない）。→ 不採用

## Consequences

- 縦走路上のサミットでも地形学的に適切な dominant peak を特定できる
- `dominant_peak_dist_m` は人手確認の参考値として常に出力する（フォールバック指標としての役割は廃止）
- いずれの delete判定ゾーンにも含まれないサミット（`summit.match_status="unmatched"`）が発生した場合は ISSUE 起票して個別対応する（merge.py を非ゼロ終了させる仕様。フォールバックは廃止。[ADR-SRS-011](ADR-SRS-011-delete-zone-polygon.md)）
