# ADR-SRS-017: 内部トランザクションカテゴリの導入

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-06 |

## Context

ADR-SRS-016 は SRS パラメータを 6（外部I/F）・7.1（ユーザー入力）・7.2（内部データ）のいずれかに一覧定義することを規約として定めている。

単一 FR 内または直結 2 FR 間でしか受け渡されないメモリ上の一時値（例: [FR-002](../20_SRS.md#fr-002-dem-階層フォールバック) 出力の生 RGB、[FR-003](../20_SRS.md#fr-003-標高デコードnodata-処理) 出力の標高値）を 7.2 に一覧化しても、情報密度が薄く保守コストが上がる。7.2 の意味（永続化される・複数 FR をまたぐ追跡対象データ）を保つため、このような一時値は別カテゴリで扱いたい。

## Decision

新カテゴリ「内部トランザクション」を導入する。

- **定義**: 特定の解析処理のスコープ内でのみ有効で、処理完了時に破棄される値。永続化されず、後続フェーズや他の解析からは参照されない
- **一覧管理**: SRS セクション 7.2 内部データ一覧の対象外とする
- **記述方法**: 発生する FR の入出力テーブル内に種別「内部トランザクション」として記載し、発生元 FR（または渡し先 FR）を明示する
- ADR-SRS-016 の規約はそのまま有効。本 ADR は規約の例外条項として位置付ける

## Alternatives

- **7.2 に一覧追加で対応**: 既存規約との一貫性は保てるが、リスト保守コスト増・一覧の意味が希薄化する
- **「トランザクション」単独命名**: 既存カテゴリ「外部I/F」「内部データ」と並列性が崩れる（命名体系が「内部」を共通化している）

## Consequences

- SRS §8.1（内部データ一覧）が「永続化される・複数 FR をまたぐ」データに絞られ、一覧の意味が明確化する
- FR の入出力欄に「発生元 FR」を明示する運用が必要（今回 [FR-002](../20_SRS.md#fr-002-dem-階層フォールバック)/[FR-003](../20_SRS.md#fr-003-標高デコードnodata-処理) から適用。他 FR への適用は別 ISSUE で順次対応）
- ADR-SRS-016 を読む際は本 ADR も併読すべき（規約の例外）
- `docs/00_GLOSSARY.md`「システム境界・データ分類」表・`CLAUDE.md` 分類ルール表・SRS §2.2・§8.1 に「内部トランザクション」の記述を追加する

## 改訂注記（2026-06-14）

当初の定義文「独立した中央データ構造として保持されない」は多義的で、Union-Find を内包するピーク候補リストや 2 次元配列の解析範囲標高グリッドのように**構造が大きくても解析スコープローカルな値**まで誤排除するように読めた。本改訂では定義の判断基準を「構造の大小」から「**スコープ**（特定の解析処理の範囲内でのみ有効で、処理完了時に破棄されるか）」へ精緻化した。ピーク候補リストのピクセル座標は当該解析範囲グリッド上の相対座標であり、解析完了後に破棄される（[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) で緯度経度へ変換して CSV 化）。これはスコープ基準で内部トランザクションに分類されることを裏付ける。

また [FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) 出力の例示名称を「コル情報」から「**ピーク候補・コル情報リスト**」へ改称した（[ADR-SRS-020](ADR-SRS-020-peak-col-pair-record.md) 参照）。ピーク候補リストとコル情報を別々の内部トランザクションとして渡すとジョインキーが未定義になる問題が判明したため、1レコード＝1ピーク＋その Key コルの per-peak 対応レコード形式に一本化した。
