# ADR-SRS-038: FR 入出力テーブルの外部I/F 網羅性規約

| 状態 | 採用・実装済み |
| 決定日 | 2026-06-27 |

## Context

SRS（`docs/20_SRS.md`）の各機能要件（FR）は「入力」「出力」テーブルを持ち、扱うデータを
種別（外部I/F・ユーザー入力・内部データ・内部トランザクション）付きで列挙する
（分類定義: [ADR-SRS-016](ADR-SRS-016-data-classification-external-user-internal.md)）。

レビューで **FR-019（HTML ビューア機能仕様）の入力テーブルが外部I/F を網羅していない**ことが判明した。
FR-019 は実行時にブラウザから取得する外部I/F のうち、

- 等高線オーバーレイ用の地理院標高タイル・地理院基準点タイル（任意・ON 時取得）は入力テーブルに記載していたが、
- 背景タイル4種（国土地理院標準地図・国土地理院淡色地図・OSM・OpenTopoMap）は記載していなかった。

両者はいずれも「ブラウザが実行時に取得する外部I/F」である。背景タイルは説明欄
（FR-019 本文）と [6.6 出力: GeoJSON作業用 HTML ビューア](../20_SRS.md#66-出力-geojson作業用-html-ビューア)・
セクション8（外部システムとの I/F）には記載されていたため、FR-019 を単独で読むと
抜けが自己完結して見え、見落とされていた。

全22 FR を精査した結果、外部I/F を入出力テーブルから落としているのは FR-019 が唯一だった。
他 FR（FR-001/009/011/012/015/020/021 等）は外部I/F をテーブルに列挙しており、
**「入出力テーブルは扱う外部I/F を網羅して列挙する」という暗黙規約**が既に確立していたが、
明文化されていなかったため逸脱を機械的に検出できなかった。

## Decision

1. **規約の明文化**: 各 FR の入出力テーブルは、その FR が扱う**全外部I/F を網羅して列挙する**。
   実行時取得（ブラウザからのタイル取得等）・キャッシュ再利用（ローカル保存済みタイル等）を
   問わず、外部I/F として扱うものは記載対象とする。この規約を `docs/CLAUDE.md` の
   「外部I/F・ユーザー入力・内部データ・内部トランザクションの分類ルール」節に明記する。

2. **集約先の原則（生成 FR と実行時 I/F の切り分け）**: 生成 FR が出力する成果物が
   実行時に取得する外部I/F は、その**実行時挙動を定義する FR に集約**して列挙する。
   具体的には、HTML ビューアの背景タイル・等高線タイル・基準点タイル等の実行時取得は、
   ビューアの実行時挙動を定義する **FR-019 に集約**する。HTML を生成するだけの
   生成 FR（[FR-013](../20_SRS.md#fr-013-html-ビューア生成)・[FR-020](../20_SRS.md#fr-020-公開用-html-ビューア生成)）は
   入力＝GeoJSON / localStorage、出力＝HTML ファイルであり、実行時タイルを I/O に持たない。
   公開用ビューアの実行時挙動も FR-019 の機能セットを再利用する。したがって
   **FR-013/FR-020 の入出力テーブルに実行時タイルを記載しない**ことは正しく、再指摘の対象としない。

3. **本件への適用**: FR-019 入力テーブルに背景タイル4種を「外部I/F・必須」として追記する
   （基図はいずれか1つを常時表示するため必須。ON/OFF 取得のオーバーレイ系は従来どおり任意）。
   あわせて、未記載だった国土地理院標準地図・淡色地図の出典を `ref/SOURCES.md` に追加し、
   `docs/00_GLOSSARY.md` に用語を追加する。

## Alternatives

**B. 実行時の外部依存を §6.6/§8 に集約し、FR 入力表からは外す**（不採用）
背景タイル・CDN ライブラリ（Leaflet/SheetJS/JSZip）が §6.6/§8 のみに記載されている
現状に合わせ、FR-019 のオーバーレイ系タイルも §6 側へ寄せて「入力表はビューアが取得・加工する
データに限定」する案。一貫性は得られるが、「FR の入出力表で全 I/F を俯瞰できる」という
既存22 FR の大勢（外部I/F は各 FR 表に列挙）から FR-019 だけを外す方向であり、
プロジェクトのこれまでの記述流儀（入出力は表に載せる）に反する。却下。

**C. 現状維持＋注記のみ**（不採用）
「背景タイルは §6.6 が正本なので FR-019 表には重複記載しない」と注記で根拠化する案。
しかしオーバーレイ系タイルは FR-019 表に載っているため、同じ実行時外部I/F 内で
「載せる／載せない」の判断基準が分かれたままになり、非対称が解消されない。却下。

## Consequences

- FR の入出力テーブルが外部I/F の単一の俯瞰点になり、「この FR が外部と何をやり取りするか」を
  表だけで把握できる状態が全 FR で揃う。
- 逸脱検出の根拠が明文化されたことで、横串の規約適合チェック（spec-panel の
  仕様レビュアー視点）が「入出力表は全外部I/F を列挙しているか」を機械的に照合できる。
- 生成 FR と実行時 I/F の切り分け原則を明記したため、FR-013/FR-020 にタイルが
  無いことを「抜け」と誤検出するのを防げる。
- 既存 FR で同種の網羅漏れが将来見つかった場合も、本 ADR と CLAUDE.md 規約を根拠に是正する。
