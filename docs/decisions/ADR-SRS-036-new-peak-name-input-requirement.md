# ADR-SRS-036: new ピーク山岳名入力の必須性と未入力時のエクスポート挙動

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-26 |

## Context

HTML ビューア（[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様)）は new（新規）ピークに対し
「山岳名JP」「山岳名EN」入力フィールドを提供するが、各フィールドが必須か任意か、また未入力のまま
申請書（[FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成)）をエクスポートした場合の挙動が未定義だった。

申請書の「追加」行は山岳名JP/EN をビューア入力から転記する（[FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成) ※1）。
未入力のままエクスポートすると名称が空欄の申請書が生成され得るため、申請成否に関わる。

本ツールが生成するのは申請書の**ドラフト**であり、SOTA 日本支部への公式申請とその最終的な
妥当性判断は日本支部の担当者が行う、という運用前提を踏まえる必要がある。

## Decision

1. **山岳名JP を必須、山岳名EN を任意とする**。
   - 山岳名JP は国内での目視確認・台帳（geojson_v{N} の `summit_name_jp`）整合の主キー的役割を担うため必須。
   - 公式リストのローマ字/英語名は最終的に SOTA 日本支部担当者が公式登録時に確定するため、
     ツール側では任意入力とする（担当者が補完できる）。
2. **未入力時はブロックせず警告して続行可とする**。
   - 山岳名JP が未入力の new ピークが存在する状態で申請書（FR-011）をエクスポートする場合は、
     該当ピークの一覧を警告表示する。
   - ただし公式申請の最終判断は SOTA 日本支部担当者が行うため、エクスポート自体は禁止せず、
     ユーザー判断で空欄のまま続行することも許容する（ソフト必須）。

## Alternatives

- **山岳名EN を必須にする（SOTA 公式リスト準拠）**: SOTA 公式リストはローマ字/英語名が必須だが、
  公式英語名の確定は日本支部担当者の役割であり、ツール利用者に確定を強制すると運用と齟齬するため不採用。
- **JP・EN 両方必須**: 名称整合は高まるが、英語名をツール利用段階で確定できないケースで作業が
  滞り運用が硬直するため不採用。
- **未入力をブロック（ハード必須）**: 不正な申請書ドラフトは確実に防げるが、最終判断を担う
  日本支部担当者の運用（空欄で受け取り後から補完）を妨げるため不採用。
- **無警告で空欄出力**: 実装は単純だが、名称欠落を見逃した不完全なドラフトを生むリスクがあるため不採用。
  警告は出す。

## Consequences

- FR-019 の山岳名入力 UI（new ピーク）に「JP 必須・EN 任意」「未入力時は警告して続行可」を明記する（本コミットで実施）。
- FR-011 ※1 に必須性の参照を追記し整合させる（本コミットで実施）。
- 上記の必須性定義は本 ADR で決着する。
- 警告 UI・必須判定の実装は別タスク（HLD・実装フェーズ）で行う。
