# ADR-SRS-028: 全国一括突合への純化・FR-010 削除・範囲外/DEM 無効フラグ廃止

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-18 |

---

## Context

[FR-009（SOTAリスト突合）](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の設計レビューで、部分解析前提の機構が全国一括運用では不要であることが明確になった。

1. **[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) にメッシュリスト入力が存在する**: 任意入力として「1次メッシュコードリスト」が [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の入力に含まれ、[FR-010（削除候補のスコープ）](../20_SRS.md#fr-010-削除候補のスコープ) を通じて「解析範囲内サミットのみを削除候補対象とする」絞り込み機構が動作していた。

2. **不備フラグが役割混在**: `is_out_of_range_summit`（解析範囲外サミット検出 → 止める用）と `is_dem_invalid_summit`（DEM NODATA 検出 → 記録のみ）が同列に「不備フラグ」として定義されていた。全国一括前提では発生し得ない状態を「止める」フラグとして定義することは死蔵になる。

3. **運用前提の不明確さ**: SRS は「全国一括突合」と「部分解析後突合」のどちらを前提とするかを明示していなかった。

ユーザー確認を経て、本プロジェクトの運用前提を **全国一括突合（解析は地域ごとに分けても [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) は全国ピーク CSV を統合してから一括実行）** に確定した。

## Decision

### 1. 運用前提を全国一括突合に確定

[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) は常に全国の `merged_peak.csv` / `merged_peak.geojson` を入力として一括突合する。部分解析での逐次突合はサポートしない。

### 2. FR-010「削除候補のスコープ」を削除

全国一括突合では「解析範囲外サミット」という概念が発生しない（全 SOTA サミットが解析対象）。FR-010 は原理的に不要であり、SRS から削除する。

### 3. FR-009 のメッシュリスト入力を削除

FR-010 の削除に伴い、[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の入力から「1次メッシュコードリスト（任意）」を削除する。

### 4. `is_out_of_range_summit` / `is_dem_invalid_summit` を削除

- `is_out_of_range_summit`: 全国一括前提では全サミットが解析対象のため、「範囲外」は発生しない。死蔵フラグとして削除。
- `is_dem_invalid_summit`: DEM NODATA 座標への対処は [FR-005](../20_SRS.md#fr-005-ピーク候補検出) 相当の前段処理で対応すべきものであり、[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) での後処理フラグとして定義することは責務が不適切。加えて全国一括突合では発生頻度が実用上ゼロに近い。削除する。

残る不備フラグは以下の3つに限定する（いずれも全国一括前提でも発生し得る本質的な不備）:

| フラグ | 意味 |
|---|---|
| `is_unmatched_summit` | 既存サミット座標がどのゾーンにも含まれない（解析欠落・閾値不備を示す） |
| `is_area_incomplete` | ポリゴンが解析範囲外で途切れた（AZ 完結保証が崩れた） |
| `is_key_col_unresolved` | N=6 まで使い切っても Key コル未確定 |

## Alternatives

| 案 | 却下理由 |
|---|---|
| FR-010 を残す（現状維持） | 全国一括前提では機能しない死蔵コードになる。YAGNI 原則：将来部分解析が必要になった時点で改めて設計する |
| `is_out_of_range_summit` / `is_dem_invalid_summit` を記録のみ（stop しない）フラグとして残す | 全国一括前提では発生しないフラグを残してもテスト・説明コストが増えるだけ。死蔵フラグは削除を優先する |

## Consequences

1. **[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の不備フラグが3つに簡素化**: 責務が明確な3フラグのみになり、異常終了条件が一義的になる
2. **[UR-003](../10_URD.md#ur-003) のカバレッジは維持**: `delete` サミットの特定は [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の `peak.match_status` 判定で引き続き行われる。FR-010 が担っていた「範囲外誤削除防止」は全国一括前提では概念として不要
3. **将来の部分解析対応**: 部分解析が必要になった場合は本 ADR を見直し、FR-010 相当の機構を再設計する（ADR を参照することで判断根拠が残る）
4. **実装への影響**: コードに FR-010 相当のロジックがあれば削除が必要
