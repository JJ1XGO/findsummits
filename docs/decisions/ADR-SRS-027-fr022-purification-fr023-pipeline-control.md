# ADR-SRS-027: FR-022 純化・FR-023 解析パイプライン制御新設・N 扱い再設計

| 状態 | 採用・未実装 |
| 決定日 | 2026-06-18 |

> ※ 本 ADR は [ADR-SRS-004](ADR-SRS-004-level14-max-pooling-isolated-peaks.md)（エスカレーション責務を FR-022 に置いていた箇所）および [ADR-SRS-019](ADR-SRS-019-land-summit-highest-peak-handling.md)（陸地最高峰確定を FR-022 が行うとしていた箇所）の該当部分を supersede する。

---

## Context

[FR-022（コル充足判定）](../20_SRS.md#fr-022-コル充足判定) の設計レビューで以下の問題が明確になった。

1. **判定とオーケストレーションの混在**: FR-022 が「コル充足かどうかを判定する」という本来の責務に加え、「N エスカレーションループ制御」「FR-014 呼び出し」「FR-008 再実行」「陸地最高峰の海面確定」まで担っていた。

2. **陸地最高峰 override が再統合で消える**: ループ内の FR-008 再実行で `merged_peak.csv` が再生成されるたびに、FR-022 が行った陸地最高峰の海面確定が上書き消滅する可能性があった（FR-022 が override を適用するのは FR-008 実行後であるため）。

3. **N の曖昧さ**: FR-022 がファイル名 `key_col_unresolved_peaks-<N>.csv` から N を抽出して N+1 を FR-014 に渡す設計であり、N が「前段階のタグ」なのか「次段のウィンドウサイズ」なのかが一意でなかった。

4. **フェーズ番号の不一致**: SRS 3.3.1 マトリクスでは「フェーズ2 = 3×3 解析」「フェーズ3 = 広域解析」と定義されているが、3.3.2 俯瞰図および FR 本文では「フェーズ2-1」「フェーズ2-2」「フェーズ3（統合）」という別表記が混在していた。

## Decision

### 1. FR-022 を純粋判定に純化

FR-022 の責務を「`merged_peak.csv` を読んで未確定ピーク有無と座標リストを返す」のみに限定する。

- **削除した責務**: N エスカレーション制御、FR-014 呼び出し、FR-008 再実行、陸地最高峰の海面確定
- **残した責務**: `key_col_resolved=false` の抽出・`key_col_unresolved_peaks-<N>.csv` の出力・未確定有無の返却
- N は呼び出し元（FR-023）から渡される生成段階タグとして受け取る（ファイル名からの逆算禁止）

### 2. FR-023「解析パイプライン制御」を新設（新 §4.3）

N カウンタの唯一の所有者として新コンポーネントを追加する。実装は shell スクリプト。

- フェーズ2〜4 の実行順序を統括する
- N = 3（フェーズ2 の生成段階タグ）からカウントし、フェーズ3 では N=4→5→6 でインクリメント
- FR-014 に N を明示引数として渡す（ファイル名から N を導出しない）
- FR-008 + FR-018 を毎回セットで呼び出す
- FR-022 の判定結果（「ゼロ」/「残あり」）を受け取ってループ継続・終了を決定
- 各段（フェーズ2 / フェーズ3 の各 N / フェーズ4）は独立起動可能とする（段階的確認のため）
- 自動ループも提供する

### 3. 陸地最高峰の海面確定を FR-008 に移管（案B）

陸地最高峰の海面確定（`key_col_resolved=true`・Key コル = 0m）を **FR-008 が `merged_peak.csv` を生成するたびに適用**する。

これにより：
- FR-008 を何度再実行しても確定値が保持される（override が消えない）
- FR-022/FR-023 は陸地最高峰を特別扱いしない（判定ロジックの単純化）

[ADR-SRS-019](ADR-SRS-019-land-summit-highest-peak-handling.md) の「層2: FR-022 での手動確定」を本 ADR の決定で FR-008 に移管する。ADR-SRS-019 の層1（FR-006 海面確定規則）は変更なし。

### 4. N の意味の明確化（生成段階タグ）

`key_col_unresolved_peaks-<N>.csv` のファイル名における N は **「その一覧を生成した段階のウィンドウサイズ」**（生成段階タグ）である。

- `-3`: 3×3（フェーズ2）完了後に残ったピーク群
- `-4`: 4×4（フェーズ3 第1段）完了後に残ったピーク群

FR-014 に渡す「次段 N」は FR-023 が計算・管理する。FR-014 はファイル名から N を導出しない。

### 5. フェーズ番号の統一

3.3.1 マトリクスを正とし、全 FR 本文・俯瞰図・設定パラメータ表を統一する。

| 旧表記 | 新表記 |
|---|---|
| フェーズ2-1 | フェーズ2 |
| フェーズ2-2 | フェーズ3 |
| フェーズ3（統合・判定） | 統合時（FR-008）/ 番号なし |

## Alternatives

| 案 | 却下理由 |
|---|---|
| FR-022 にループ制御を残す（現状維持） | 判定とオーケストレーションの混在が継続する。ユーザーは「各段で止めて確認したい」という強い要求を持っており、shell レベルで段階制御できる構造が適切 |
| FR-023 を CSV 操作可能な Python スクリプトとして実装 | ユーザーは「全てを一気に処理する案（案A）」ではなく「1段ずつ確認できる案（案B）」を要求。shell スクリプトが最小実装で目的を達成できる |
| 陸地最高峰を FR-023 が再適用（案A） | FR-023 は shell スクリプトであり CSV 操作を行わない。FR-008 が毎回適用する案B のほうが単純かつ確実 |
| ファイル名から N を逆算して N+1 を渡す（旧方式） | N が「生成段階タグ」なのか「次段サイズ」なのかが曖昧になる。N カウンタを FR-023 が一元管理することで混線を防ぐ |

## Consequences

1. **FR-004 は変更なし**: 3×3 通常モード専用のオーケストレーションとして純化済み。本 ADR の影響を受けない
2. **FR-014 の入力変更**: 「解析範囲サイズ N」の渡し方が「ファイル名から抽出 + N+1 算出」→「FR-023 からの明示引数」に変わる（実装への影響あり。todo.md に追記）
3. **FR-008 の入力追加**: 陸地最高峰リストが FR-022 入力から FR-008 入力に移動する（実装への影響あり。todo.md に追記）
4. **陸地最高峰リストの分類変更**: ユーザー入力（7.1.4）→ 内部データ（7.2）。日本全土1次メッシュコードリストと同性質（システムが `params/` に保持するデータ）
5. **FR-022 の実装が大幅に縮小**: ループ・FR-014 呼び出し・FR-008 再実行・陸地最高峰確定のロジックを除去（実装への影響あり。todo.md に追記）
6. **FR-023 の新規実装が必要**: shell スクリプト。todo.md に追記
7. **ADR-SRS-004 更新**: 「FR-022 がエスカレーション/陸地最高峰を所有」の記述を本 ADR へ forward link
8. **ADR-SRS-019 更新**: 「層2（FR-022 での手動確定）」→「FR-008 での適用」に改訂
